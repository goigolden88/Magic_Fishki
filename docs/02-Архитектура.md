# Архитектура

## Модель данных

```ts
type Game = {
  id: string            // ULID
  name: string          // «Пятница у Кирилла»; по умолчанию — дата
  date: string          // YYYY-MM-DD, день игры
  rate: number          // рублей за фишку: 0.5 — фишка по 50 копеек
  players: Player[]
  entries: Entry[]
  casino?: CasinoRound[] // раунды казино (Р-13); нет — казино не было
  mode?: 'poker' | 'mixed' | 'casino' // режим (Р-29): покер, покер и казино, только казино; нет — по данным
  closed?: boolean      // игра закрыта: записи не правятся без «Открыть снова»
  demo?: boolean        // демо-данные — удаляются одной кнопкой
  updatedAt: string     // ISO 8601
}

type Player = {
  id: string
  name: string          // копия имени на момент игры: правка постоянных её не трогает
  regularId?: string    // id постоянного игрока (Р-12); нет — гость
}

type Regular = { id: string; name: string } // постоянный игрок: id не меняется при переименовании (Р-12)

type Entry = {
  id: string
  playerId: string
  kind: 'buyin' | 'rebuy' | 'cashout'
  chips: number         // целое, > 0
  at: string            // ISO 8601, ставится само
}

type CasinoRound = {    // раунд казино (Р-13): сумма долей — ноль
  id: string
  amounts: { playerId: string; kopecks: number }[] // доля участника в копейках, целое, не 0
  at: string            // ISO 8601, ставится само
}

type Settings = {
  defaultRate: number     // курс новой игры; по умолчанию 0.5
  players?: Regular[]     // постоянные игроки — отмечены в новой игре (Р-07, Р-12); нет — пусто
  quickAmounts?: number[] // быстрые суммы у «Закуп», «Докуп», «Выход» (Р-07); нет — [500, 1000, 2000]
  compareWindow?: number  // окно сравнения на карточке игрока (Р-15): целое 3–10; нет или вне — 5
}
```

**Режим игры** (Р-29, `src/calc/gameMode.ts`): `gameMode` — поле `mode`, а нет его (игры до Р-29, игра из Телеграма, итог стола покера, демо) — по данным: раунды без покерных записей — `'casino'`, и то и другое — `'mixed'`, иначе — `'poker'`. «Новая игра» пишет выбранный режим (`createGame`, `NewGame.mode`, нет — `'poker'`); у `'casino'` записей нет, курс — из настроек. Смена — только `addCasino` («покер» → «покер и казино») и `addPoker` («только казино» → «покер и казино», курс — из настроек); обратно нет. Игра без поля при первой правке на экране игры получает режим по данным. Режим меняет только вид и создание игры: итоги, переводы и статистика считаются по записям и раундам, как раньше.

**Связь с постоянным игроком** (Р-12): `regularId` ставится при создании игры из отмеченных постоянных (по их id), при добавлении участника на экране игры и в игре из Телеграма — по точному совпадению имени (`linkRegulars`, `src/model.ts`); в игре из стола покера онлайн — по постоянному, под которым игрок сел (Р-20). Переименование постоянного меняет только `name` в настройках — id и связи прошлых игр остаются.

## Расчёт — `src/calc/`

- **Итог игрока:** `out − in`, где `in` — сумма закупов и докупов, `out` — сумма выходов (обычно один). В рублях — `× rate`, хранится и считается в копейках, округление — до копейки
- **Сходится ли игра:** сумма `in` всех = сумма `out` всех. Не сходится — итог показывает разницу словами и переводы не считает: «не хватает 500 фишек: у кого-то не записан выход»
- **Казино** (Р-13, `src/calc/casino.ts`): раунд вводится строками `Эрик, Артём +150` — каждый названный получает число в рублях, без знака — плюс; имя дважды — сложено (`parseRound`). Раунд добавляется, только если в ноль и все строки разобраны; имя не из игры — новый участник только казино (без покерных записей, связь с постоянным по имени). Три итога участника (`gameResult`): покер — копейки из фишек (`playerTotals`), казино — сумма долей, итого — их сумма. Игра сходится — покер сходится и все раунды в ноль; игра без закупов — только казино
- **Раунд казино с картами** (#76, Р-26, `src/calc/casinoDeal.ts`): вариант `DealKind` — `'holdem'` (`HOLDEM`, по 2 карты) или `'omaha'` (`OMAHA`, по 4) из `src/poker/cards.ts`; столы по `BOARD_CARDS` = 5 карт; по умолчанию `DEFAULT_TABLES` = 5 столов и ставка `DEFAULT_STAKE` = 100 ₽. Одна колода: карт — участники × карты руки + столы × 5 (`cardsUsed`), `maxTables` / `maxPlayers` — предел по колоде (холдем на 5 столах — до 13, омаха — до 6; омаха на 7 участников — до 4 столов). Раздача (`dealFromDeck`; `newDeal` — из `shuffle(buildDeck(...))` на Web Crypto): в руки по одной по кругу, затем столы по 5 подряд; меньше двух участников, повтор, ноль столов или карт не хватит — ошибка. Стол (`boardResult`) — победители `winners` в порядке участников, `bestHand().name` и у каждого победителя лучшая пятёрка (`best`, `bestHand().cards`, #96). Делёж (`roundShares`): банк = ставка × участников, поровну на столы (`tableParts`: копейки остатка — по одной первым столам), часть стола — его победителям поровну, остаток — по одной первым по порядку участников; у каждого `won` и `net` = `won` − ставка, сумма `net` — ноль. `sharesToRound` — раунд по именам (`ParsedRound`) для `addRound`: записанный раунд — обычный `CasinoRound`, нулевые доли не пишутся
- **Статистика постоянных игроков** (`src/calc/stats.ts`): только закрытые игры без `demo`, только участники с `regularId` из настроек (гости — нет); строка — по id постоянного, имя — из настроек. Итоги — покер, казино и итого (Р-13); итог в рублях — сумма копеек «итого» по играм (у каждой свой курс); игр и в плюсе; лучший и худший вечер — по рублям «итого»; докупы — число записей `rebuy`, среднее за игру. Порядок — по рублям, сверху самый большой плюс, без игр — внизу
- **Динамика игрока** (`src/calc/trend.ts`, `playerTrend`): те же закрытые игры без `demo`, в которых есть участник с этим `regularId` (дважды в игре — один вечер), новые первыми — как на «Играх» (дата, затем `id`). Окно N — `Settings.compareWindow` (Р-15). Окна — последние N и предыдущие до N, по «итого»: итог в копейках, в плюсе, средний итог за игру (целые копейки), докупов в среднем. Разница последних с предыдущими по каждому показателю; предыдущих меньше N — итог и «в плюсе» предыдущих приводятся к числу последних (по средним); лучше — больше, для докупов — меньше
- **Лучший и худший промежуток** (Р-15, `src/calc/trend.ts`, `playerSpans`): те же вечера игрока в порядке дат (старые первыми); скользящее окно из N вечеров подряд — сумма «итого» в копейках, день первой и последней игры. Лучший — наибольшая сумма, худший — наименьшая; могут пересекаться; при равенстве — более поздний. Вечеров меньше 2N — промежутков нет, есть число вечеров
- **Покер за всё время** (Р-55, #164, `src/calc/pokerAllTime.ts`, `allTimeHud`): счётчики `HudCounts` постоянного по всем записям хранилища `hands` (`allHands`) — сумма `addHand({}, раздача)` по его месту в каждой раздаче, тот же подсчёт, что HUD вечера за столом. Раздача для `addHand` (`HudHand` в `src/poker/hud.ts` — что он читает: места, кнопка, большой блайнд, ходы, круги торгов игры) — из `record` (карты на телефонах) или `live` (живые карты; большой блайнд — `EveningTable.bb`, в турнире — стартовый). Место постоянного — имя равно имени постоянного и это не гость: есть в `EveningTable.regulars`; у записей до Р-55 — только по имени, а двое с этим именем в одной раздаче — раздача не в счёт. Удалённый вечер — его записей нет, они не в счёте. Показ — `countsView` (`src/calc/pokerView.ts`, его же зовёт `hudView` стола): раздач нет — `null`, меньше `HUD_FEW_HANDS` — `few`
- **Переводы:** жадно — самый большой должник платит самому большому получателю, пока все не на нуле. Переводов не больше «игроков с ненулевым итогом − 1». Проверка в тестах — пример со скриншота: 6 игроков, 5 переводов. Без казино — в фишках, рубли из фишек; с казино — по «итого» в копейках (Р-13): при дробном курсе сумма копеек покера может отличаться от нуля на копейку — она остаётся без перевода
- **Итог стола покера онлайн → игра** (Р-20, `src/calc/pokerGame.ts`, `gameFromTable`): из стола на момент конца — название и дата (сегодня), курс из настроек ведущего. Участники — по порядку посадки: сидящие — имя и `regularId` из стола, ушедшие — из записи `leave` (нет имени — «Ушёл со стола»); постоянный, севший снова, — тот же участник; гость — без `regularId`. Записи по журналу фишек: закуп — `buyin`, докуп — `rebuy` (`to − from`), уход — `cashout` с остатком; в конце — `cashout` каждому сидящему со стеком. Раздача не доиграна — отменяется: у сидящих стек до неё, ушедшему из неё возвращается поставленное, докуп, одобренный в ней, — `rebuy` и в стек. Правка стека записей не даёт — фишки могут не сойтись. Ноль фишек — без `cashout`. Сходится — игра `closed`, иначе открыта
- **Итог турнира → игра** (#78, Р-28, `src/calc/pokerGame.ts`, `gameFromTournament`): та же модель `Game`, курс `TOURNAMENT_RATE` = 1 (фишка игры — рубль). Название «Турнир ДД.ММ.ГГГГ», дата — сегодня. Участники — `tournament.entrants` по местам за столом (имя и `regularId` — из стола или из записи `leave`). Записи: каждому вход — `buyin` на бай-ин (`settings.tournament.buyIn`, время — старт турнира), каждый ребай (`rebuy` в журнале фишек) — `rebuy` на бай-ин, приз — `cashout` по месту (`standings`): фонд — все бай-ины (`prizePool`), проценты — `tournament.prizes`, рубли — вниз, остаток — первому месту (`prizeAmounts`); ноль — без `cashout`. Итог каждого = приз − все его бай-ины, игра в ноль — `closed`. На экране — `tournamentResults`: место, имя, бай-инов, приз, итог
- **Форма «Кэш» / «Турнир»** (#78, `src/calc/tournamentForm.ts`): `TournamentForm` — поля строками; `tournamentForm(players)` — сначала кэш, анте 0, турнир — `DEFAULT_TOURNAMENT`, свои призы — по числу игроков; `formSettings` — `format`, `ante`, `tournament` для настроек стола, ошибка — словами стола (`tournamentError`, `prizesError`); пустое поле — 0. `levelText` — «10/20, анте 2», `prizeRuleText` — правило призов словами из `PRIZE_RULES`
- **Стол на одном телефоне** (Р-21, `src/calc/localTable.ts`): тот же `TableState` и `handle` из `src/poker/`, только сообщения шлёт экран, а не сервер; от чьего имени — решается здесь. `LocalTable` — `{ id, table, gameId }`: свой id стола (`ulid()` при «Начать») и id записанной игры (`null` — не записана). `startLocalTable` — от 2 до `LOCAL_MAX_SEATS` = 10 игроков (`localStartError`), садятся по порядку, ведущий по правилам — первый, `maxSeats` — 10 (место новым); `actFor` — ход от того, чья очередь (`toActId`); `hostDo` — команда от `hostId`; `rebuyNow` — докуп сразу: `rebuy` от игрока и `rebuyAnswer` с «да» от ведущего (в раздаче — в стек после неё, `pendingRebuy`); `seatPlayer` — новый игрок; `removePlayer` — ведущего: сначала `passHost` следующему по месту, затем `remove`, отказ — стол как был; `localTableView` — `tableView` от ведущего, кнопки хода — того, чей ход (`actionsView`), «меня» за столом нет; `parseLocalTable` — стол из памяти устройства, не похоже — `null`. `online` у игроков — `true` с посадки, `setOnline` не зовётся; таймера хода, перерыва и раздачи «сама» нет — настройки времени по умолчанию (выкл), `onTime` не зовётся (#75). Турнир и анте (#78): `startLocalTable` берёт ещё `ante`, `format` и `tournament`; `tournamentRebuyFor` — «Ребай» от имени выбывшего; «Перерыв» (`pause` через `hostDo`) — только в турнире, часы уровней — по часам телефона; ожидание ребая (#94) закрывает экран раз в секунду (`closeRebuyWait` вместо будильника), «Закончить турнир» — `endTournament` через `hostDo`
- **Бот покера** (#117, Р-38; стили — #139, Р-45, `src/calc/bot.ts`): `botMove(view, botId, style, random, styles, hud?)` — чистая функция: вход — вид стола глазами бота (`viewFor`), выход — допустимый ход (`BetAction`; не его ход — `null`). Читает только свои карты, общие, открытые всем карты соперников (`publicCards`), банк (`committed` всех), ставку и позицию — подай ему весь стол, ответ тот же (тест). Кнопки хода — `actionsView`: намерение «пас / колл / повысить до N» превращается в допустимый ход — пас при возможном чеке — чек; повысить нельзя — олл-ин, если есть, иначе колл; сумма — от `raise.min` до `raise.max`, весь стек — `allin`. Ещё читает журнал ходов раздачи (`hand.log`) и стили соперников-ботов `styles` (по id; подписи видны всем за столом; человек — без стиля, «неизвестный»). Стили (`BotStyle`, `BOT_STYLES`): маньяк `maniac`, колл-станция `station`, нит `nit`, ABC `abc`, ТАГ `tag`, ЛАГ `lag`; уровни стола (`BotLevel`, `BOT_LEVELS`, `LEVEL_STYLES`): «Новичок» `novice` — маньяк, колл-станция, нит; «Любитель» `amateur` — ABC; «Сильный» `strong` — ТАГ, ЛАГ; «Вперемешку» `mixed` — все шесть. `pickStyles(level, count, random)` — стили на ботов без повтора, пока хватает, затем новый круг. **Руки до флопа** (`src/calc/botRanges.ts`): 169 классов от сильных к слабым — таблица `HAND_ORDER` в коде; «верхняя доля» руки `topShare` — какая часть 1326 сочетаний не хуже (тузы ≈ 0,005, 7-2 разной масти ≈ 1); ширина открытия первым `openWidth(стиль, ходят после, мест)` — таблица по стилю: 5 ходят после (UTG) … 1 (малый блайнд), хедз-ап — шире всего; ширины чтения `WIDTHS` (вход уравниванием, колл повышения, колл большого блайнда, 3-бет, 4-бет, доля блефов-блокеров `blockerBluff` — одномастные A5–A2 и связанные). **Чтение соперника** (`src/calc/botRead.ts`): `readHand(hand)` — ходы журнала с улицей, уровнем повышения и размером (прибавка к ставке круга / банк после уравнивания); `rangeOf(read, id, стиль, стол, известные карты)` — вес каждой из 1326 рук: до флопа — по позиции и ходу (открытие, вход уравниванием, колл, 3-бет, 4-бет), после — сужение каждым ходом на столе своей улицы: место руки в нынешнем диапазоне по силе `v` (`boardInfo(стол)` — доля рук, которые она бьёт, и прибавка за флеш-дро и стрит-дро до ривера; в памяти модуля — 8 последних столов): чек — у верхних 20 % вес × «медленная игра» стиля; колл — без части верхних 8 % и нижних 25 %; ставка меньше 0,55 банка — широкий диапазон с перевесом сильных; крупнее — поляризованный: вэлью сверху (доля по стилю), середина × 0,1, блефы снизу в доле `bluffShare(размер, стиль)` = размер / (1 + 2 · размер) × множитель стиля (маньяк 1,8, ЛАГ 1,15, ТАГ 1, неизвестный 0,8, ABC 0,45, колл-станция 0,35, нит 0,15); повышение поверх ставки — уже. `equityVs(свои, стол, диапазоны, random, досдач)` — доля банка против диапазонов: на ривере точно по каждой руке (несколько соперников — произведение), до ривера — `2 × BOT_SAMPLES` досдач с руками соперников из их весов. **Стили** — функции до флопа и после: маньяк, колл-станция, нит — сила после флопа против случайных рук (`BOT_SAMPLES` = 60 досдач, не больше 3 соперников) и дро (`drawOf`), каждый со своим изъяном; ABC — то же, минус 0,06 за каждую ставку соперников после флопа, колл без пары или туза — нет, на ривере нужна сила 0,5 + 0,3 × ставка / банк; ТАГ и ЛАГ — до флопа открытие по таблице (2,5 ББ, малый блайнд — 3, по ББ за вошедших), изоляция вошедших, 3-бет поляризованно (верх по ширине повысившего + блефы-блокеры, чаще против тех, кто сдаётся), колл по позиции и цене, 4-бет и олл-ин по ширине 3-бета; стек ≤ `PUSH_FOLD_BB` = 15 ББ — пуш/фолд; ставка больше 40 % стека — олл-ин. После флопа — сила против диапазонов соперников; вэлью — когда впереди той части диапазона, что уравняет (`topOfRange`, доля по стилю: колл-станция 0,85 … нит 0,3); размер — от стола (сухой флоп — 1/3 банка, мокрый и тёрн — 2/3, ривер — 1/2–3/4, против колл-станции крупнее); продолжение ставкой, полублеф дро, вторая ставка на тёрне и блеф на ривере — с частотой по стилю соперника (кто как сдаётся), после двух улиц без успеха блеф вдвое реже; медленная игра с сильной рукой, рейз-блеф на одиночную ставку до ривера; колл — по цене банка (до ривера без позиции +0,06); защита банка — лучшая часть своего диапазона (`rangeOf` себя, как видит соперник) с частотой (1 − ставка / (банк + ставка)) × множитель стиля соперника, если рука бьёт хоть часть блефов. **Омаха** (#147, Р-46, `src/calc/botOmaha.ts`; вариант с `fromHand: 2` и четырьмя картами): до флопа — очки четырёх карт `omahaPoints` (пары, одномастность — двойная выше, три и четыре одной масти хуже двух; связанность — сколько разных рангов в окне из пяти, младшие стриты дешевле; старшие карты; «висящая» карта — минус) и доля `omahaTop` — по выборке 20 000 рук со своим зерном (одна на все телефоны); бот берёт `omahaTop / OMAHA_SPREAD[стиль]` (диапазоны омахи шире холдемных: нит 1,5, ТАГ и ЛАГ 1,2, прочие 1,15) и решает теми же функциями стиля; блеф-повышение — `omahaBluff` (двойная одномастная с тузом своей масти, «линия» из четырёх от восьмёрки); короткий стек сильного — «олл-ин» повышениями в банк только с верхними руками, повысил — до конца. После флопа — по правилу «ровно две из руки и три со стола» (`handScore` варианта): слабые и ABC — доля против случайных рук, растянутая от средней (`OMAHA_STRETCH` = 1,5), дро — `omahaDraw` (флеш-дро — две своих масти и две на столе, натс-дро, карт к стриту: 8 и больше — «обёртка»); сильные — диапазоны соперников выборкой `omahaRangeOf` (до 120 рук: отбор по `preflopWeight` с омаховыми долями, сужение по ходам `narrow`, доля вэлью в ставке × 0,6 — в омахе ставят ближе к натсам), `omahaEquityVs`, `omahaTopOfRange`, место своей руки в своём диапазоне `omahaRankInRange`; натсы на ривере (`omahaBoardRank` — ни одна пара невидимых карт не сильнее) — ставка в банк и повышение; давят дро к натсам; без медленной игры; колл до ривера — с запасом +0,1, защита банка × 0,85. Холдем этим не задет: `preflopWeight` и `narrow` — общие правила чтения из `botRead`. Прочие игры (шорт-дек; стол против ботов им не играет; бот всё равно ходит допустимо) — сила до флопа счётом Чена (`preflopStrength`), сильные после флопа — как ABC. Чтение соперников за вечер (#146, Р-47; `src/calc/botHud.ts`): `hud` — HUD вечера всех за столом (`Hud`, счётчики по ходам, без карт; стол ботов подаёт `table.hud` в `botStep`, докуп его не сбрасывает); ТАГ и ЛАГ читают каждого соперника `readRival(id, styles, hud, omaha)` → `RivalRead` (`who` — типаж для чтения диапазона, `profile` — поправки `Profile`: `folds`, `defend`, `barrel`, `calls`, `steal`; `ats`, `cb` — доли за вечер от 10 возможностей, иначе `null`). Меньше `HUD_FEW_HANDS` = 30 раздач — как подписан (бот) или ABC (человек и любой без подписи); с 30 — VPIP, PFR и AF смешиваются с ожиданием от подписи (`EXPECT`) весом 20 раздач и дают типаж `typeOf` по порогам `BOUNDS` (холдем: маньяк — VPIP ≥ 45 % и PFR ≥ 30 %, колл-станция — VPIP ≥ 40 % и AF < 1 или PFR < 10 %, нит — VPIP < 16 %, ЛАГ — VPIP ≥ 28 % и PFR ≥ 21 %; у омахи VPIP-пороги выше: 50 / 45 / 19 / 33 %); AF > 3,5 (не нит и не маньяк) — «давит»: защита банка шире, на ставки сдаётся реже; нит по HUD без подписи нита — от нита только кражи шире (`steal`) и сдача на его повышения (`defend`), руки и прочее — как у среднего; явный вор (ATS ≥ 40 %) — его открытие с поздней позиции шире; часто продолжающий ставкой (CB ≥ 75 %) — чаще повышение вместо колла в позиции. ## Покер через интернет — `src/poker/` (Р-14, Р-17)

Этап 1 — кэш-игра в холдем «живые карты, цифровые фишки»: карты настоящие, ставки, банки, очередь хода и стеки ведёт программа. Этап 2 (Р-23) — режим комнаты «карты на телефонах»: колоду тасует сервер комнаты, карты сдаёт и банки по силе руки раздаёт программа. Чистые функции без DOM, IndexedDB и модулей Node — их берут и сайт, и сервер комнат; время — параметром `now`, случайное — Web Crypto. Экран — «Покер онлайн» (Р-19, ниже в «Экранах»).

- **Стол** (`table.ts`, `TableState`) — обычный JSON: сервер сохраняет его между сообщениями и поднимает снова. У игрока за столом — `regularId`: постоянный игрок (Р-12), под которым он сел, или `null` — гость; под одним постоянным за столом сидит один («Этот игрок уже за столом»). `handle(state, from, message, now)` — новое состояние или отказ с причиной, состояние при отказе не меняется. Ведущий (`hostId`) — создатель стола; передаёт ведение сам, а вне сети дольше минуты (`setOnline`, `HOST_TAKEOVER_MS`) — его берёт любой игрок. Посадка — закуп `startingStack`; докуп — запрос игрока, «да» ведущего; во время раздачи — в стек после неё. Правка стека ведущим — только между раздачами. Место (`seat`, 0…`maxSeats − 1`) — при посадке первое свободное; пересадка (`moveSeat`, #98) — сам или ведущий за другого, только между раздачами и в «Перерыв» (в раздаче — «Пересесть можно между раздачами»), только на свободное (занято — «Место уже занято — выберите другое»: двое на одно — сел первый); фишек не стоит, кнопка следующей раздачи — к следующему по номеру месту от прошлой кнопки, без «мёртвой кнопки»: пересевший может пропустить или повторить блайнд. Убрать игрока ведущий может, если тот не в раздаче или уже сбросил карты; ещё в раздаче (в том числе ва-банк) — отказ «Игрок в раздаче — уберите после неё». Уходит с остатком: стек, а в раздаче — то, что не поставил, плюс одобренный в ней докуп. Журнал фишек (`chipLog`): закуп, докуп и правка — кто, было, стало; отказ в докупе; уход (`leave`) — кто убрал, остаток, имя и `regularId` ушедшего (у записей до #60 имени нет). Игра (#80, Р-33) — `settings.game`: `'holdem'`, `'omaha'` или `'shortdeck'` (#81, Р-34) (нет поля — холдем, и у столов до #80), при любых картах; `settings.limit` — `'pot'` или `'nolimit'`, только у омахи (нет поля — пот-лимит); `limitFor(settings)` — предел новой раздачи: омаха — по настройке, холдем и шорт-дек — всегда `'nolimit'`; значение не из списка — отказ в `settingsError`

WebSocket со сном (`acceptWebSocket`): в памяти ничего не держится — стол читается из хранилища на каждом сообщении и пишется после; кто на соединении — отметка на сокете (`serializeAttachment`). Сразу после подключения комната шлёт `lobby`: список и id постоянных, уже сидящих за столом. Первое сообщение клиента — `join`: с верным токеном — возврат на своё место (старое соединение того же игрока закрывается), без токена или с чужим — посадка новым: с `regularId` — под постоянным, имя из списка («Такого игрока нет в списке комнаты» — если нет), без него — гостем под именем; отказ посадки — причина и свежий `lobby`. `reseat` (только ведущий, не себя) — новый токен игроку: ведущему `reseated` для ссылки, старый токен больше не пускает, соединения игрока закрываются (`CLOSE_REPLACED`), он вне сети. Остальное — в `handle` стола; на `start` при картах на телефонах комната тасует колоду (`newDeck`: `shuffle(deckFor(gameFor(settings)))`, случайность — `env.random`, нет — Web Crypto) и подаёт её столу — тем же путём и раздаче «сама» из будильника. Удачный ход — всем вошедшим `state` (с `now` — временем сервера): каждому свой вид стола (`viewFor` по игроку соединения — без колоды и чужих закрытых карт; при живых картах — весь стол), отказ — `error` только приславшему; `ended` — тоже в виде телефона. Возврат по токену и «пересадить» приносят свои карты — они в столе на сервере. Чужая версия в любом сообщении — «обновите приложение», соединение закрыто. Закрылось последнее соединение игрока — он вне сети (`setOnline`). На `PING` отвечает сама платформа, объект не просыпается (`setWebSocketAutoResponse`); последний признак жизни соединения — позднее из времени ответа (`getWebSocketAutoResponseTimestamp`) и входа (`joinedAt` в отметке). Ведущий ведёт стол как раньше; ведущий вне сети, пока не вошёл
- **История раздач** (#113): каждая раздача — своей записью хранилища объекта `hand:000012` (`handKey`, номер с нулями — по порядку ключей; `HistoryHand` полностью, с `hidden`), не в записи `room`: та пишется целиком и уходит всем на каждый ход, а значение хранилища — не больше 128 КиБ. Пишется (`keepHand`) после удачного хода и срабатывания будильника, до записи стола, когда `finishedHand` что-то дал: раздача окончилась (ходом, по таймеру) или «Показать» переписал её запись. Вошедший шлёт `history` — ему одному ответ `history`: все записи по порядку номеров (`list` с префиксом `hand:`), каждая в его виде (`handFor`); не вошедшему — «Сначала войдите в комнату». Состояние стола в `state` от числа раздач не растёт
- **Пропавшие молча** (#64): будильник один на комнату; пока за столом кто-то в сети, он срабатывает раз в `CHECK_MS` = 20 с (вход ставит его, если назначенный дальше). Соединение игрока молчит дольше `SILENT_MS` — закрывается (`CLOSE_SILENT`, клиент переподключается), игрок без других соединений — вне сети с последнего признака жизни; в сети по столу, а соединения нет (перезапуск сервера) — вне сети с момента проверки. Худший случай до «вне сети» — `PING_MS` + `SILENT_MS` + `CHECK_MS` ≈ 50 с после пропажи; «Взять ведение» — через `HOST_TAKEOVER_MS` после последнего признака, меньше двух минут. Никого в сети — будильник на сутки после последнего хода. Ведение само не переходит
- **Сроки стола** (#75): тот же будильник — ближайшее из суток после последнего хода, `now + CHECK_MS` (кто-то в сети) и `nextDeadline` стола (`nextAlarm`); после каждого удачного сообщения и входа он переводится раньше, если нужен раньше (`wake`), и не отодвигается. Срабатывание — сначала живость, затем `onTime` стола с колодой `newDeck`: истёкший ход, раздача «сама» или закрытие ребая, пока его ждут (#94: турнир окончен и без ведущего в сети), — всем `state`; рано или повторно — стол не меняется и не рассылается. Ход по таймеру и раздача «сама» `lastMoveAt` не двигают: брошенная комната доигрывает, пока все не «пропускают раздачи» (два истечения подряд), и стирается через `IDLE_MS` после последнего хода людей. Ведущий вне сети или телефоны спят — сроки идут сами
- **Конец комнаты:** ведущий шлёт `finish` или будильник видит сутки без ходов (`IDLE_MS`; ставится при создании, а без игроков в сети — на сутки после последнего хода) — всем `ended` со столом на этот момент, соединения закрыты, хранилище стёрто (с историей раздач), место в реестре освобождено. Повтор будильника после стирания ничего не делает
- **Реестр** (объект `Registry`, один) — коды живых комнат, не больше `MAX_ROOMS` = 10. Код — 6 знаков без похожих (`CODE_ALPHABET`). Реестр полон — комнаты старше минуты спрашиваются, живы ли (`alive`), мёртвые вычеркиваются
- **Пределы бесплатного плана** кончились — ошибка подключения к серверу; сайт и учёт вечера от сервера не зависят

## Хранение

IndexedDB, база `magic_fishki`, версия 3: хранилища `games` (ключ `id`), `settings` (одна запись) и `hands` — раздачи прошлых вечеров покера. Новая версия — шагом миграции, старые записи не теряются.

- **1** — хранилища `games` и `settings`
- **2** (Р-12) — `settings.players` из строк в `{ id, name }` с новыми id в прежнем порядке; участникам сохранённых игр с точно тем же именем — `regularId`; остальные поля игр, в том числе `updatedAt`, не меняются. Другая вкладка на версии 1 закрывает базу по `onversionchange`
- **3** (Р-37, #114) — новое пустое хранилище `hands`; игры и настройки не трогаются

**Раздачи прошлых вечеров** (`hands`, Р-37) — запись на раздачу `SavedHand` (`src/calc/evenings.ts`): `{ evening, code, startedAt, number, hand }`, ключ — `[evening, number]`, индекс `evening`; `hand` — `HistoryHand` (`src/poker/history.ts`) как пришла за столом: у онлайн-стола — вид этого игрока (`handFor`: свои карты взявшего без вскрытия — только у него). Вечер (`Evening`) — `id`, `code` (код комнаты; стол на телефоне — `null`), `startedAt` — первая запись журнала фишек стола (закуп ведущего при создании); `id` комнаты — «код-начало» (`roomEvening`: код освобождается после конца и может повториться), стола на телефоне — «local-id стола» (`localEvening`). Та же раздача второй раз заменяет запись (`saveHands`, одной транзакцией) — дублей нет, после «Показать» — с показанными картами. `listEvenings` — по первой записи каждого вечера (курсор индекса `nextunique`) и число раздач (`count`), новые сверху (`byNewest`); `eveningHands` — раздачи вечера по номерам; `deleteEvening` — все раздачи вечера одной транзакцией. С Р-54 (#163): у записи ещё необязательные `table` — `EveningTable` `{ me, game, limit, sb, bb, ante, maxSeats, tournament, regulars? }` (`eveningTable`: игрок этого телефона — `null` у стола на одном телефоне — и игра стола, для выгрузки; блайнды — для живых карт, у которых в раздаче их нет; `regulars` — с Р-55 (#164): постоянные стола, id игрока за столом → `regularId`, сидящие и ушедшие по записи ухода, кого нет — гость; у записей до Р-55 поля нет) и `mine` — свои карты этого телефона в раздаче (`useMyCards` запоминает их по номеру, пока раздача идёт: запись раздачи карт сбросивших не хранит); у записей до Р-54 полей нет, хранилище и версия базы те же. `saveHands` без `mine` оставляет `mine` прежней записи. Против ботов — свой вечер `bots-id стола с ботами` (`botsEvening`, `isBotsEvening`; строка — «Против ботов»), раздачи пишутся по ходу тем же `useHandCopy` из `bots.history` в виде человека (`handFor`); «Закончить» их не стирает. `eveningRecords` — записи вечера целиком, `allHands` — все записи, `handKeys` — ключи, `restoreHands` — запись из копии одной транзакцией. **Выгрузка** (`src/calc/handText.ts`): `handsText` — раздачи текстом истории покер-румов (шапка `PokerStars Hand #<начало вечера, с><номер, 4 знака>: <игра> <лимит> (sb/bb) - <дата начала вечера>`, стол и кнопка, места и стеки, анте и блайнды — по местам от кнопки, `Dealt to` — свои карты (`mine`, иначе взятые без вскрытия или вскрытые), ходы по улицам с суммами прибавки, борд, непокрытая ставка, вскрытие, `collected`, `*** SUMMARY ***`); вечера — по началу, в вечере — по номеру; чужие карты — только вскрытые и показанные. Файл — `fishki-hands-ГГГГ-ММ-ДД.txt` («Выгрузить» у вечера, день вечера), `fishki-hands-all-ГГГГ-ММ-ДД.txt` («Выгрузить все», сегодня). Входят в файл-копию с формата 3.

**Заметки об игроках** (Р-56, #165, `src/calc/playerNotes.ts`) — данные этого телефона, не игр: localStorage (`src/screens/pokerStorage.ts`, ключи `fishki.poker.notes` и `fishki.poker.noteLabels`), не IndexedDB; в комнату и на сервер не уходят. `PlayerNotes` — по имени игрока без пробелов по краям (`noteKey`): `{ [имя]: { color: NoteColor | null, text } }`; одноимённые делят заметку, переименование её не переносит. Цветов восемь (`NOTE_COLORS`: `id`, точка `hex`, подпись по умолчанию — «фиш», «маньяк», «тайтовый», «регуляр», «блефует», «не верить», «колл-станция», «другое»); `NoteLabels` — только переименованные подписи, пусто или как по умолчанию — снова по умолчанию (`setLabel`). **Файл-копия** (Р-11) — `fishki-ГГГГ-ММ-ДД.json`: `{ app: 'magic_fishki', format: 4, savedAt, games, settings, hands, notes, noteLabels }`, игры — все, кроме `demo: true`; в формате 4 (Р-56) `notes` — заметки об игроках (`PlayerNotes`), `noteLabels` — переименованные подписи цветов; у формата 4 нет поля или заметка не читается (цвет не из восьми, текст не строка) — ошибка; копии 1–3 читаются без заметок; восстановление (`mergeNotes`) дописывает заметки имён, у которых здесь заметки нет, и подписи цветов, не переименованных здесь, — свои не трогаются; в формате 3 (Р-54) `hands` — все записи хранилища раздач как есть (`SavedHand`); у формата 3 нет списка или запись не читается (ключ, `hand.number` не равен `number`) — ошибка с номером раздачи; копии 1 и 2 читаются с пустым `hands`; восстановление дописывает раздачи, которых нет по `[evening, number]` (`planRestore` → `hands`, `restoreHands`), записанные не трогаются; в формате 2 (Р-12) постоянные игроки — `{ id, name }`, у участников — `regularId`; раунды казино (Р-13) — в игре, формат тот же: раунд не в ноль — битая игра, копия без поля — игра без казино; режим игры (Р-29) — в игре, формат тот же: нет поля — режим по данным, значение не из трёх — битая игра; окно сравнения (Р-15) — в `settings`, формат тот же: копия без него или с окном вне 3–10 читается с окном 5. Пришёл `state` с новым видом — у всех меняется сразу. Свои: «Попросить докуп» (стартовый стек и быстрые суммы из настроек, не больше предела стола), «Пропускать раздачи». Ведущий: «Да»/«Нет» на докупы, «Начать раздачу» (в перерыв её нет) и «Перерыв» / «Продолжить» — между раздачами в панели внизу экрана, в раздаче «Перерыв» — в карточке «Ведущий», между раздачами — «Настройки стола» (свёрнуто: та же форма времени, что у новой комнаты, «Сохранить» — `tableSettings`, «действует со следующей раздачи»; при раздаче «сама» без перерыва — подсказка сначала нажать «Перерыв»; там же «Статистику игроков (HUD) видят» — `tableSettings.publicHud`, #79), всегда, и в раздаче, — «Вид стола» (свёрнуто, #77: «Сукно» и «Рубашка карт», как у новой комнаты; касание — сразу `look`, без «Сохранить»; при живых картах — «рубашка на экране не видна»), «Пропустить ход», после торгов — победители каждого банка (один претендент — отмечен сам), «Раздать банки»; нажатие на игрока — «Поправить стек» (между раздачами), «Пропускает раздачи», «Место N · пересадить на место» — кнопки свободных мест (`MoveSeat`, #98; в раздаче — «пересадить можно между раздачами»), «Пересадить на новое устройство» (ссылка с местом — «Поделиться ссылкой»), «Передать ведение», «Убрать со стола»; «Закончить игру» — после вопроса (раздача не доиграна — «она отменится») итог стола игрой в IndexedDB этого телефона (`gameFromTable`, `saveGame`, Р-20), затем `finish`; без связи игра всё равно записывается из последнего стола, комната — при следующем нажатии или сама через сутки. Записанный итог помнится по «код/место» (`localStorage`, последние 20): повтор второй игры не пишет, только шлёт `finish`; рядом — «Игра записана в историю» и «Открыть игру». Ведущий вне сети дольше `HOST_TAKEOVER_MS` — у остальных «Взять ведение». Анте и турнир (#78; `TableView.ante`, `tournament` — `TournamentView` из `tournamentView(table, me, now)`, у места — `place`): строка над столом — «Блайнды 10/20, анте 2» раздачи (между раздачами — следующей), в турнире — «Турнир · …»; под столом у всех — `TournamentPanel` (`src/screens/Tournament.tsx`): «Уровень N: блайнды, анте», «До следующего мм:сс» (`clockText`, от времени сервера) и следующие блайнды, «Перерыв — часы стоят у всех», ребай до конца уровня или «Ребай закрыт», бай-ин, фонд и призы по местам; ждём ребай (#94; `TournamentView`: `waiting`, `waitLeft`, `canEnd`) — сверху «Ждём ребай — до конца уровня N, мм:сс» (ребай до конца последнего уровня — без отсчёта) и пояснение, у ведущего — «Закончить турнир» после вопроса (`endTournament`; на столе на телефоне — тоже); у выбывшего места — «N место». «Мои фишки» в турнире — бай-ин, «Ребай за N ₽ — стек …» (пока открыт; `tournamentRebuy`), «Пропускать раздачи»; запроса докупа нет. Ведущий: первая раздача — «Начать турнир»; «Настройки стола» — в кэше ещё «Анте», в турнире до старта — «Призы по местам» (`PrizeFields`, `tableSettings.prizes`); у игроков — без «Поправить стек»; окончен — «Места и призы» (`TournamentResults`), «Записать игру» — `gameFromTournament` и `finish`; не окончен — «Закончить игру» после вопроса закрывает комнату без записи. «Комната закрыта» у турнира — места и призы вместо стеков. «Поделиться» в шапке — ссылка на стол в системное «Поделиться» или в буфер. ## Сборка и выкладка

Vite, `base: '/Magic_Fishki/'`; PWA — `vite-plugin-pwa` (манифест, работник, иконки, `apple-touch-icon` для iPhone). Манифест — `fishki.webmanifest`, `id` — `/Magic_Fishki/fishki`, запуск — `/Magic_Fishki/?app=fishki` (Р-06, Р-08): не меняются никогда. На Android Play Защита может предупредить «для более ранней версии Android» — «Всё равно установить» (оболочку собирает Chrome, не мы). GitHub Pages — `.github/workflows/deploy.yml` на пуш в `main`.

Сервер комнат — `.github/workflows/server.yml` на пуш в `main` с правкой `server/`, `src/poker/` или зависимостей: тесты, типы сервера, `npm run server:deploy` (`wrangler deploy`); нет секретов `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` — выкатка пропускается. В «Проверках PR» — `npm run server:check` (типы) и `npm run server:build` (`wrangler deploy --dry-run`).
