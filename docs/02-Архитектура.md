# Архитектура

## Модель данных

```ts
type Game = {
  id: string            // ULID
  name: string          // «Пятница у Кирилла»; по умолчанию — дата
  date: string          // YYYY-MM-DD, день игры
  rate: number          // рублей за фишку: 0.5 — фишка по 50 копеек
  players: Player[]
  entries: Entry[]
  casino?: CasinoRound[] // раунды казино (Р-13); нет — казино не было
  closed?: boolean      // игра закрыта: записи не правятся без «Открыть снова»
  demo?: boolean        // демо-данные — удаляются одной кнопкой
  updatedAt: string     // ISO 8601
}

type Player = {
  id: string
  name: string          // копия имени на момент игры: правка постоянных её не трогает
  regularId?: string    // id постоянного игрока (Р-12); нет — гость
}

type Regular = { id: string; name: string } // постоянный игрок: id не меняется при переименовании (Р-12)

type Entry = {
  id: string
  playerId: string
  kind: 'buyin' | 'rebuy' | 'cashout'
  chips: number         // целое, > 0
  at: string            // ISO 8601, ставится само
}

type CasinoRound = {    // раунд казино (Р-13): сумма долей — ноль
  id: string
  amounts: { playerId: string; kopecks: number }[] // доля участника в копейках, целое, не 0
  at: string            // ISO 8601, ставится само
}

type Settings = {
  defaultRate: number     // курс новой игры; по умолчанию 0.5
  players?: Regular[]     // постоянные игроки — отмечены в новой игре (Р-07, Р-12); нет — пусто
  quickAmounts?: number[] // быстрые суммы у «Закуп», «Докуп», «Выход» (Р-07); нет — [500, 1000, 2000]
  compareWindow?: number  // окно сравнения на карточке игрока (Р-15): целое 3–10; нет или вне — 5
}
```

**Связь с постоянным игроком** (Р-12): `regularId` ставится при создании игры из отмеченных постоянных (по их id), при добавлении участника на экране игры и в игре из Телеграма — по точному совпадению имени (`linkRegulars`, `src/model.ts`); в игре из стола покера онлайн — по постоянному, под которым игрок сел (Р-20). Переименование постоянного меняет только `name` в настройках — id и связи прошлых игр остаются.

## Расчёт — `src/calc/`

- **Итог игрока:** `out − in`, где `in` — сумма закупов и докупов, `out` — сумма выходов (обычно один). В рублях — `× rate`, хранится и считается в копейках, округление — до копейки
- **Сходится ли игра:** сумма `in` всех = сумма `out` всех. Не сходится — итог показывает разницу словами и переводы не считает: «не хватает 500 фишек: у кого-то не записан выход»
- **Казино** (Р-13, `src/calc/casino.ts`): раунд вводится строками `Эрик, Артём +150` — каждый названный получает число в рублях, без знака — плюс; имя дважды — сложено (`parseRound`). Раунд добавляется, только если в ноль и все строки разобраны; имя не из игры — новый участник только казино (без покерных записей, связь с постоянным по имени). Три итога участника (`gameResult`): покер — копейки из фишек (`playerTotals`), казино — сумма долей, итого — их сумма. Игра сходится — покер сходится и все раунды в ноль; игра без закупов — только казино
- **Статистика постоянных игроков** (`src/calc/stats.ts`): только закрытые игры без `demo`, только участники с `regularId` из настроек (гости — нет); строка — по id постоянного, имя — из настроек. Итоги — покер, казино и итого (Р-13); итог в рублях — сумма копеек «итого» по играм (у каждой свой курс); игр и в плюсе; лучший и худший вечер — по рублям «итого»; докупы — число записей `rebuy`, среднее за игру. Порядок — по рублям, сверху самый большой плюс, без игр — внизу
- **Динамика игрока** (`src/calc/trend.ts`, `playerTrend`): те же закрытые игры без `demo`, в которых есть участник с этим `regularId` (дважды в игре — один вечер), новые первыми — как на «Играх» (дата, затем `id`). Окно N — `Settings.compareWindow` (Р-15). Окна — последние N и предыдущие до N, по «итого»: итог в копейках, в плюсе, средний итог за игру (целые копейки), докупов в среднем. Разница последних с предыдущими по каждому показателю; предыдущих меньше N — итог и «в плюсе» предыдущих приводятся к числу последних (по средним); лучше — больше, для докупов — меньше
- **Лучший и худший промежуток** (Р-15, `src/calc/trend.ts`, `playerSpans`): те же вечера игрока в порядке дат (старые первыми); скользящее окно из N вечеров подряд — сумма «итого» в копейках, день первой и последней игры. Лучший — наибольшая сумма, худший — наименьшая; могут пересекаться; при равенстве — более поздний. Вечеров меньше 2N — промежутков нет, есть число вечеров
- **Переводы:** жадно — самый большой должник платит самому большому получателю, пока все не на нуле. Переводов не больше «игроков с ненулевым итогом − 1». Проверка в тестах — пример со скриншота: 6 игроков, 5 переводов. Без казино — в фишках, рубли из фишек; с казино — по «итого» в копейках (Р-13): при дробном курсе сумма копеек покера может отличаться от нуля на копейку — она остаётся без перевода
- **Итог стола покера онлайн → игра** (Р-20, `src/calc/pokerGame.ts`, `gameFromTable`): из стола на момент конца — название и дата (сегодня), курс из настроек ведущего. Участники — по порядку посадки: сидящие — имя и `regularId` из стола, ушедшие — из записи `leave` (нет имени — «Ушёл со стола»); постоянный, севший снова, — тот же участник; гость — без `regularId`. Записи по журналу фишек: закуп — `buyin`, докуп — `rebuy` (`to − from`), уход — `cashout` с остатком; в конце — `cashout` каждому сидящему со стеком. Раздача не доиграна — отменяется: у сидящих стек до неё, ушедшему из неё возвращается поставленное, докуп, одобренный в ней, — `rebuy` и в стек. Правка стека записей не даёт — фишки могут не сойтись. Ноль фишек — без `cashout`. Сходится — игра `closed`, иначе открыта
- **Стол на одном телефоне** (Р-21, `src/calc/localTable.ts`): тот же `TableState` и `handle` из `src/poker/`, только сообщения шлёт экран, а не сервер; от чьего имени — решается здесь. `LocalTable` — `{ id, table, gameId }`: свой id стола (`ulid()` при «Начать») и id записанной игры (`null` — не записана). `startLocalTable` — от 2 до `LOCAL_MAX_SEATS` = 10 игроков (`localStartError`), садятся по порядку, ведущий по правилам — первый, `maxSeats` — 10 (место новым); `actFor` — ход от того, чья очередь (`toActId`); `hostDo` — команда от `hostId`; `rebuyNow` — докуп сразу: `rebuy` от игрока и `rebuyAnswer` с «да» от ведущего (в раздаче — в стек после неё, `pendingRebuy`); `seatPlayer` — новый игрок; `removePlayer` — ведущего: сначала `passHost` следующему по месту, затем `remove`, отказ — стол как был; `localTableView` — `tableView` от ведущего, кнопки хода — того, чей ход (`actionsView`), «меня» за столом нет; `parseLocalTable` — стол из памяти устройства, не похоже — `null`. `online` у игроков — `true` с посадки, `setOnline` не зовётся
- Всё — чистые функции с тестами

## Покер через интернет — `src/poker/` (Р-14, Р-17)

Этап 1 — кэш-игра в холдем «живые карты, цифровые фишки»: карты настоящие, ставки, банки, очередь хода и стеки ведёт программа. Чистые функции без DOM, IndexedDB и модулей Node — их берут и сайт, и сервер комнат; время — параметром `now`, случайное — Web Crypto. Экран — «Покер онлайн» (Р-19, ниже в «Экранах»).

- **Стол** (`table.ts`, `TableState`) — обычный JSON: сервер сохраняет его между сообщениями и поднимает снова. У игрока за столом — `regularId`: постоянный игрок (Р-12), под которым он сел, или `null` — гость; под одним постоянным за столом сидит один («Этот игрок уже за столом»). `handle(state, from, message, now)` — новое состояние или отказ с причиной, состояние при отказе не меняется. Ведущий (`hostId`) — создатель стола; передаёт ведение сам, а вне сети дольше минуты (`setOnline`, `HOST_TAKEOVER_MS`) — его берёт любой игрок. Посадка — закуп `startingStack`; докуп — запрос игрока, «да» ведущего; во время раздачи — в стек после неё. Правка стека ведущим — только между раздачами. Убрать игрока ведущий может, если тот не в раздаче или уже сбросил карты; ещё в раздаче (в том числе ва-банк) — отказ «Игрок в раздаче — уберите после неё». Уходит с остатком: стек, а в раздаче — то, что не поставил, плюс одобренный в ней докуп. Журнал фишек (`chipLog`): закуп, докуп и правка — кто, было, стало; отказ в докупе; уход (`leave`) — кто убрал, остаток, имя и `regularId` ушедшего (у записей до #60 имени нет)
- **Раздача** (`hand.ts`) — блайнды (хедз-ап: кнопка ставит малый и ходит первой до флопа), очередь хода, улицы; кнопка — по кругу мест. Неполный олл-ин-рейз не открывает торги ходившим: им — уравнять или сбросить; неполные вместе на полный рейз — открывают. Торги закрыты на ривере, ставить больше некому или остался один — непокрытая часть ставки возвращается, банки слоями (`pots.ts`), раздача ждёт ведущего: он отмечает победителей каждого банка (`award`), делёж поровну, нечётная фишка — первому по кругу от кнопки. Ход за отошедшего — ведущий (`skip`: чек или сброс)
- **Протокол** (`protocol.ts`) — сообщения клиента и сервера, `PROTOCOL_VERSION` (сейчас 3); чужая версия — отказ «обновите приложение». Признак жизни (#64): клиент шлёт `PING` каждые `PING_MS` = 15 с, ответ — `PONG`; молчание дольше `SILENT_MS` = 30 с — соединение мёртвое. Сообщения комнаты (`RoomMessage`: `join` — с `regularId` под постоянным, `finish`, `reseat`), создание комнаты (`CreateRoomRequest`: с `roster` — отмеченные постоянные `RosterEntry`, и `regularId` ведущего; `CreateRoomResponse`), список входа (`lobby`), новое место для «пересадить» (`reseated`), конец комнаты (`ended`) — для сервера комнат. Отказы и коды закрытия, на которые экран отвечает по-своему («Комнаты нет», «Неверный пароль», `CLOSE_*`), и причина конца по «Закончить игру» (`FINISHED`) — тоже здесь, общие с сервером
- **Карты и сила руки** (`cards.ts`, Р-22) — этап 2, модуль пока никто не зовёт. Карта — строка «ранг + масть» (`'Ah'`, `'Td'`; масти `s h d c`). Вариант (`Variant`) — данные: `deck` — 52 или 36 (без 2–5), `fromHand` — `'any'` (любые 5 из руки и стола) или N (ровно N из руки, остальное со стола), `order` — комбинации от младшей к старшей; готовые `HOLDEM`, `OMAHA` (ровно 2), `SHORT_DECK` (флеш старше фулл-хауса, стрит старше тройки). Младший стрит — туз и четыре младших ранга колоды (A-2-3-4-5, A-6-7-8-9). `buildDeck` — колода по порядку; `bestHand(variant, hand, board)` — лучшая пятёрка перебором (на столе 3–5 карт): карты, комбинация, `value` для сравнения (место в `order`, затем ранги), название по-русски («Две пары, короли и семёрки»); `compareHands` — с кикерами, 0 — ничья; `winners(variant, board, contenders)` — все с лучшей рукой. Неверная запись, карта не из колоды варианта, повтор карты или неверное число карт — ошибка (`Error` с причиной)
- **Токен возврата** (`tokens.ts`) — секрет места игрока для возврата после обрыва; карту токенов хранит сервер
- Сценарии прототипа (`prototype/poker/test/`: `sidepots`, `edge`, `run-hand`, `rebuy`, `hostcontrols`) — тестами Vitest; каждый прогоняется и с сохранением состояния в JSON между сообщениями. Прототип в сборку не входит

## Сервер комнат — `server/` (Р-14, Р-18)

Cloudflare Workers + Durable Objects, Worker `fishki-poker`, адрес `https://fishki-poker.goigolden88.workers.dev/`. Тонкая обёртка над `src/poker/`: своих правил покера нет. Сборка сайта сервер не втягивает; свой `server/tsconfig.json` с типами Workers. Логика — без привязки к Cloudflare (`room.ts`, `registry.ts`, `http.ts`, тесты Vitest с подделками хранилища и соединений из `testing.ts`); `index.ts` — только привязка.

- **Запросы:** `GET /` — «Сервер покера «Фишек» работает, протокол N». `POST /rooms` — `CreateRoomRequest` → код комнаты, id и токен ведущего; из списка постоянных берутся только `{ id, name }` со строками, без повторов id, не больше `MAX_ROSTER` = 30; `regularId` не из списка — ведущий гость; проверки по порядку: версия («обновите приложение»), секрет `ROOM_PASSWORD` («На сервере не задан пароль»), пароль («Неверный пароль»), место в реестре («Комнат уже 10»), стол (`createTable`). Сайт на другом адресе — ответы с разрешением CORS. `GET /rooms/<код>` — WebSocket в комнату; кода нет — «Комнаты нет» и соединение закрыто
- **Комната** (объект `Room`, одна на код) — запись `room` в хранилище объекта: `{ code, table, tokens, roster, lastMoveAt }`; `roster` — постоянные, отмеченные ведущим (у комнат протокола 1 нет — пустой список). WebSocket со сном (`acceptWebSocket`): в памяти ничего не держится — стол читается из хранилища на каждом сообщении и пишется после; кто на соединении — отметка на сокете (`serializeAttachment`). Сразу после подключения комната шлёт `lobby`: список и id постоянных, уже сидящих за столом. Первое сообщение клиента — `join`: с верным токеном — возврат на своё место (старое соединение того же игрока закрывается), без токена или с чужим — посадка новым: с `regularId` — под постоянным, имя из списка («Такого игрока нет в списке комнаты» — если нет), без него — гостем под именем; отказ посадки — причина и свежий `lobby`. `reseat` (только ведущий, не себя) — новый токен игроку: ведущему `reseated` для ссылки, старый токен больше не пускает, соединения игрока закрываются (`CLOSE_REPLACED`), он вне сети. Остальное — в `handle` стола; удачный ход — всем вошедшим `state` со всем столом, отказ — `error` только приславшему. Чужая версия в любом сообщении — «обновите приложение», соединение закрыто. Закрылось последнее соединение игрока — он вне сети (`setOnline`). На `PING` отвечает сама платформа, объект не просыпается (`setWebSocketAutoResponse`); последний признак жизни соединения — позднее из времени ответа (`getWebSocketAutoResponseTimestamp`) и входа (`joinedAt` в отметке). Ведущий ведёт стол как раньше; ведущий вне сети, пока не вошёл
- **Пропавшие молча** (#64): будильник один на комнату; пока за столом кто-то в сети, он срабатывает раз в `CHECK_MS` = 20 с (вход ставит его, если назначенный дальше). Соединение игрока молчит дольше `SILENT_MS` — закрывается (`CLOSE_SILENT`, клиент переподключается), игрок без других соединений — вне сети с последнего признака жизни; в сети по столу, а соединения нет (перезапуск сервера) — вне сети с момента проверки. Худший случай до «вне сети» — `PING_MS` + `SILENT_MS` + `CHECK_MS` ≈ 50 с после пропажи; «Взять ведение» — через `HOST_TAKEOVER_MS` после последнего признака, меньше двух минут. Никого в сети — будильник на сутки после последнего хода. Ведение само не переходит
- **Конец комнаты:** ведущий шлёт `finish` или будильник видит сутки без ходов (`IDLE_MS`; ставится при создании, а без игроков в сети — на сутки после последнего хода) — всем `ended` со столом на этот момент, соединения закрыты, хранилище стёрто, место в реестре освобождено. Повтор будильника после стирания ничего не делает
- **Реестр** (объект `Registry`, один) — коды живых комнат, не больше `MAX_ROOMS` = 10. Код — 6 знаков без похожих (`CODE_ALPHABET`). Реестр полон — комнаты старше минуты спрашиваются, живы ли (`alive`), мёртвые вычеркиваются
- **Пределы бесплатного плана** кончились — ошибка подключения к серверу; сайт и учёт вечера от сервера не зависят

## Хранение

IndexedDB, база `magic_fishki`, версия 2: хранилища `games` (ключ `id`) и `settings` (одна запись). Новая версия — шагом миграции, старые записи не теряются.

- **1** — хранилища `games` и `settings`
- **2** (Р-12) — `settings.players` из строк в `{ id, name }` с новыми id в прежнем порядке; участникам сохранённых игр с точно тем же именем — `regularId`; остальные поля игр, в том числе `updatedAt`, не меняются. Другая вкладка на версии 1 закрывает базу по `onversionchange`

**Файл-копия** (Р-11) — `fishki-ГГГГ-ММ-ДД.json`: `{ app: 'magic_fishki', format: 2, savedAt, games, settings }`, игры — все, кроме `demo: true`; в формате 2 (Р-12) постоянные игроки — `{ id, name }`, у участников — `regularId`; раунды казино (Р-13) — в игре, формат тот же: раунд не в ноль — битая игра, копия без поля — игра без казино; окно сравнения (Р-15) — в `settings`, формат тот же: копия без него или с окном вне 3–10 читается с окном 5. Через «Поделиться» — тот же текст в `.txt` (Chrome на Android не делится `.json`); восстановление принимает оба. Восстановление: файл проверяется целиком (не копия, новее `format`, битая игра — ошибка, данные не меняются); копия формата 1 при разборе приводится к формату 2 — постоянным новые id, участникам связь по точному имени; игры, которых нет по `id`, пишутся как есть (`restoreGames`, со своим `updatedAt`, одной транзакцией), с тем же `id` — не трогаются; из настроек берутся только постоянные игроки: с тем же id — уже есть, остаётся свой; с тем же именем — один человек, связи в добавленных играх переводятся на здешний id; прочие дописываются со своим id. Разбор и слияние — `src/calc/backup.ts`.

## Экраны

- **Игры** — список, новые сверху, по годам игры (`src/calc/gameList.ts`): заголовок «2026 · игр N», нажатие сворачивает; без выбора раскрыт текущий год, а нет в нём игр — самый свежий; выбор помнится на устройстве (`localStorage`, не в IndexedDB и не в копии), новая игра — кнопкой или из Телеграма — раскрывает свой год (`src/screens/openYears.ts`). Под названием — игроков, закуплено, статус; дата — только если название не дата; только казино — «казино: раундов N». «Новая игра» (название, курс, «Участники» — галочки постоянных, сразу все; над ними «Выбрать всех», при всех отмеченных — «Снять все», `src/calc/pick.ts`), «Из Телеграма», «Покер онлайн»; в шапке — «Игроки», «Настройки» и «?» — справка
- **Игроки** (`#/players`) — статистика постоянных по всем закрытым играм: «По N закрытым играм из M»; у каждого итого в рублях, строкой — покер (рубли и фишки), казино, итого, «игр N, в плюсе M», лучший и худший вечер (сумма, дата, название), докупов всего и в среднем за игру; закрытых игр нет — «Закрытых игр пока нет»; есть демо-игры — строка «Демо-игры в статистику не входят». Касание игрока — его карточка. «Поделиться статистикой» — как «Поделиться итогом» в игре (нет игроков с играми — кнопки нет). Только читает
- **Карточка игрока** (`#/players/:id`) — за всё время, как в списке; ниже «Последние N игр» и «Предыдущие N игр» рядом (N — окно сравнения, Р-15): итог, в плюсе из N, средний итог, докупов в среднем; у последних — разница со стрелкой (▲ лучше, ▼ хуже). Игр N и меньше — только последние и «для сравнения нужно больше N игр»; от N+1 до 2N−1 — предыдущих сколько есть, пояснение «сравнение по средним»; без закрытых игр — «игр нет». Ниже — «Лучший промежуток: +X ₽, ДД.ММ–ДД.ММ (N игр)» и «Худший промежуток: −Y ₽, ДД.ММ–ДД.ММ»; игр меньше 2N — вместо них «когда закрытых игр будет 2N, сейчас M». Только читает
- **Игра** — участники; у каждого — записи и кнопки «Закуп», «Докуп», «Выход» (участник только казино — «только казино» вместо «закуп · выхода нет»); блок «Казино» — раунды и «Добавить раунд»: поле строк, предпросмотр «игрок → ₽», «Раунд не сходится на N ₽», новые имена — после подтверждения; раунд удаляется вторым нажатием, в закрытой игре не правится; итог и переводы внизу — с казино таблица «покер / казино / итого» в рублях
- **Итог для мессенджера** (`src/calc/share.ts`) — с казино строки «Покер:», «Казино:», «Итого:»; только казино — «Казино:», заголовок без курса. Статистика игроков (`statsShareText`) — «Статистика · » и основание, по строке на игрока с играми в порядке экрана: имя, итого, «игр N, в плюсе M»; казино не в ноль — «(покер …, казино …)»
- **Настройки** — курс по умолчанию, постоянные игроки, быстрые суммы (Р-07); «Покер онлайн» — «Адрес сервера» (Р-19): пусто — постоянный (`DEFAULT_SERVER`), свой — вида `https://…`, сохраняется кнопкой в `localStorage`; новые комнаты и входы идут на него; «Окно сравнения, игр» — кнопки − и + от 3 до 10, сохраняется сразу (Р-15); «Копия игр»: «Сохранить копию», «Поделиться копией» (где браузер умеет делиться файлами), «Восстановить из копии» — «Добавлено N, уже были M» (Р-11); после «Сохранить копию» — «Файл отдан браузеру — проверьте, что он сохранился»; строка «Последняя копия — N дней назад · игр после неё: M» (Р-16): момент и день последней отданной копии — в `localStorage` этого устройства (`src/screens/lastBackup.ts`, не в IndexedDB и не в копии), пишутся после «Сохранить» и после отправки через «Поделиться» (закрытое меню — нет); «после неё» — игры без демо с `updatedAt` позже копии; копии не было — «Копию на этом устройстве ещё не делали» (`lastBackupText`, `src/calc/backup.ts`); «Демо-данные» (Р-04): «Добавить демо-данные» пишет выдуманные игры (`demoGames`, `src/calc/demo.ts`: две закрытые, одна с казино, и одна открытая без выхода; день — от сегодня; участники — гости, без `regularId`; у каждой `demo: true`) через `restoreGames`; демо уже есть — кнопка неактивна; «Удалить демо-данные» — `deleteDemoGames`: одной транзакцией все игры с `demo: true` и только их; постоянные игроки не меняются
- **Из Телеграма** (`#/import`, Р-10) — вставка скопированных сообщений `#rebuy` / `#cashout` и казино → сверка (дата, курс, игроки: закуп, докупы, выход; добавить, переименовать, объединить, убрать; «не разобрано: N строк»; сходимость — той же функцией) → «Создать игру» — обычная игра со временем сообщений. Разбор — `src/calc/telegram.ts`. Казино (Р-13): строки сообщения без тега (`parseRound`; `Казино:` первой строкой — заголовок) — один раунд на сообщение; `#debt Эрик Аскару 500` и строки сообщения без тега после него — каждая раунд «первый −N, второй +N». Имя раунда связано с участником сверки, если подходит ровно одному: полное имя или первое слово, без регистра, «ё» = «е», можно с одной буквой дательного (`у`, `ю`, `е`, `и`); двое или никого — выбрать руками («Кто это?») или «Новый участник, только казино» (без закупа). Раунд не в ноль помечен «не сходится на N ₽», правится строками или убирается; игру не создать, пока есть неразобранные имена или раунды с ошибкой
- **Покер онлайн** (`#/poker`, Р-14, Р-19) — «Новая комната»: пароль компании (запомнен — «Ввести другой»), «Играют» — галочки постоянных (сразу все; над ними «Выбрать всех», при всех отмеченных — «Снять все», `src/calc/pick.ts`), «Вы за столом» — один из отмеченных (помнится на устройстве) или своё имя, блайнды (сначала `DEFAULT_SETTINGS` стола — 5/10) и стартовый стек (сначала закуп по умолчанию) → `POST /rooms` → место ведущего запоминается, открывается стол. Неверный пароль — пароль забывается, поле снова; нет ответа — «Нет связи с сервером»; другая версия — «Обновите приложение». «Мои столы» — комнаты, где на устройстве есть место; «Войти по ссылке» — ссылка или код из 6 знаков. Разбор ссылок, адрес сервера и слова отказов — `src/calc/pokerLink.ts`. Рядом с «Новая комната» — «Стол на этом телефоне» (Р-21): «Играют» — галочки постоянных (сразу все, «Выбрать всех» / «Снять все»), гости по имени (✕ — убрать), блайнды и стартовый стек — те же поля, что у комнаты; «Начать» неактивна, пока за столом меньше двух или больше 10 (подпись — почему); стол сразу в память устройства, открывается `#/poker/local`. Стол на телефоне уже есть — вместо кнопки «Стол на этом телефоне идёт»: «Продолжить стол» и «Удалить стол» (с вопросом, игра не пишется). Память браузера не работает (проверка записью и чтением) — предупреждение, что стол пропадёт после закрытия
- **Стол на этом телефоне** (`#/poker/local`, Р-21; под код комнаты не подходит) — тот же стол, что у комнаты (`PokerTable`, банки, прошлая раздача — общие с `PokerRoom.tsx`), вид — `localTableView`; без шапки «Поделиться» и без «ведущий — …». Кнопки хода — за того, чей ход: «Ход: имя», после хода — следующему (ключ карточки — по тому, чей ход: сумма снова с минимума). Карточка «Ведущий»: «Начать раздачу», после торгов — победители банков и «Раздать банки» (`AwardPanel`); «Игроки» — нажатие: «Докупить» (стартовый стек и быстрые суммы, своё число; сразу, в раздаче — «в стек после раздачи»), «Поправить стек» (между раздачами), «Пропускает раздачи», «Убрать со стола»; «Посадить игрока» — постоянные, которых нет за столом, или гость по имени. Отказ правил — строкой предупреждения. Нет «Пересадить», «Передать ведение», «Взять ведение», «вне сети», запросов докупа. Каждое изменение — весь `LocalTable` в `localStorage` (`fishki.poker.local`, `src/screens/pokerStorage.ts`) и в памяти страницы: без памяти браузера стол живёт до закрытия, на экране — предупреждение. «Закончить игру» — после вопроса (раздача не доиграна — «она отменится»): `gameFromTable` → `saveGame` → отметка `gameId` в столе → стол стирается → «Игра записана в историю», стеки и «Открыть игру»; не записалось — стол на месте. Стол с отметкой при открытии вторую игру не пишет — сразу стирается и показывает «Открыть игру». «Удалить стол» — после вопроса стирается без записи. Сеть не нужна от начала до итога
- **Стол** (`#/poker/:код`; `#/poker/:код/:игрок/:токен` — ссылка «пересадить»: место запоминается, из адреса убирается) — соединение `src/screens/useRoom.ts`: WebSocket на адрес сервера; есть место на устройстве — `join` с токеном, нет — список «Кто вы?» из `lobby` (сидящие — неактивны, «за столом») и «Гость» с именем. Обрыв — «Нет связи с сервером», новая попытка через 1, 2, 4, 8, затем каждые 10 с (`retryDelay`), сразу — когда сеть вернулась или приложение открыли снова (после сна дольше 15 с соединение открывается заново). Каждые `PING_MS` — `PING` серверу, и в фоне тоже; на открытом экране сервер молчит дольше `SILENT_MS` — соединение открывается заново. Конец комнаты или «Комнаты нет» — «Комната закрыта» со стеками и итогом против закупа, место забывается; у ведущего, записавшего итог, — «Игра записана в историю» и «Открыть игру», у остальных после «Закончить игру» — «Игра закончена, итог — у ведущего»; другая версия — «Обновите приложение»; место открыто на другом устройстве — «Вернуться сюда»; токен больше не пускает — снова «Кто вы?». Что показать — `src/calc/pokerView.ts` (`tableView`, чистая функция): места по порядку — стек, ставка улицы, D, позиция в раздаче (`positionLabels` от кнопки по числу сданных: «BTN», «SB», «BB», «UTG», поздние с конца — «CO», «HJ», «LJ», «MP», «UTG+1»; хедз-ап — «BTN/SB» и «BB», как при сдаче), ведущий, вне сети, пропускает, пас, олл-ин, чей ход; банк — всё вложенное за раздачу; основной и побочные — после торгов, а во время — только когда кто-то олл-ин (верхний слой одного игрока — неуравненная ставка, не банк). Вид — овальный стол (`src/calc/pokerLayout.ts`): я внизу по центру, остальные по порядку мест по часовой (`aroundTable`, `seatSpot`); у места — имя (длинное — многоточием), стек, подпись позиции, D, пометка «олл-ин» / «вне сети» / «пропуск» / «пас»; чей ход — подсвечен, сбросивший — приглушён; ставка улицы — перед местом ближе к центру; в центре — улица, банк, побочные (когда их больше одного) и чей ход; под столом — банки с претендентами. На 360 px девять мест — без прокрутки; на компьютере стол не шире 560 px. Кнопки хода — у всех в раздаче, активны только в свой ход: «Пас», «Чек» или «Колл N», «Олл-ин N» (нельзя — кнопки нет); в свой ход, если можно ставить или повышать не только олл-ином, — ползунок от минимума до олл-ина шагом малого блайнда, последний шаг — до олл-ина (`betSlider`, `sliderAmount`, `sliderIndex`); колесо мыши над ним — на шаг, страница не крутится (`stepAmount`); быстрые «Мин», «½ банка», «Банк», «Олл-ин» и своё число двигают ползунок; кнопка «Ставка N» (ставки на улице нет) или «Рейз до N»; нет на минимум или неполный олл-ин не открыл торги — ползунка нет. Свои: «Попросить докуп» (стартовый стек и быстрые суммы из настроек, не больше предела стола), «Пропускать раздачи». Ведущий: «Да»/«Нет» на докупы, «Начать раздачу», «Пропустить ход», после торгов — победители каждого банка (один претендент — отмечен сам), «Раздать банки»; нажатие на игрока — «Поправить стек» (между раздачами), «Пропускает раздачи», «Пересадить на новое устройство» (ссылка с местом — «Поделиться ссылкой»), «Передать ведение», «Убрать со стола»; «Закончить игру» — после вопроса (раздача не доиграна — «она отменится») итог стола игрой в IndexedDB этого телефона (`gameFromTable`, `saveGame`, Р-20), затем `finish`; без связи игра всё равно записывается из последнего стола, комната — при следующем нажатии или сама через сутки. Записанный итог помнится по «код/место» (`localStorage`, последние 20): повтор второй игры не пишет, только шлёт `finish`; рядом — «Игра записана в историю» и «Открыть игру». Ведущий вне сети дольше `HOST_TAKEOVER_MS` — у остальных «Взять ведение». «Поделиться» в шапке — ссылка на стол в системное «Поделиться» или в буфер. Пароль компании, свой адрес сервера, места по кодам комнат, «кто я» ведущего и записанные итоги — `localStorage` устройства (`src/screens/pokerStorage.ts`), не в IndexedDB и не в копии
- **Справка** (`#/help`) — свёрнутые разделы (`<details>`): по одному на экран (и «Покер онлайн»), «Как считаются переводы», «Данные», «Если что-то не так». Текст — `src/screens/helpText.ts`; числа в нём — из тех же констант, что у экранов (курс, закуп и быстрые суммы по умолчанию, окно сравнения: умолчание и границы, блайнды новой комнаты, минуты до «Взять ведение»), цифрами в тексте не пишется — проверяет тест. Только описывает

## Сборка и выкладка

Vite, `base: '/Magic_Fishki/'`; PWA — `vite-plugin-pwa` (манифест, работник, иконки, `apple-touch-icon` для iPhone). Манифест — `fishki.webmanifest`, `id` — `/Magic_Fishki/fishki`, запуск — `/Magic_Fishki/?app=fishki` (Р-06, Р-08): не меняются никогда. На Android Play Защита может предупредить «для более ранней версии Android» — «Всё равно установить» (оболочку собирает Chrome, не мы). GitHub Pages — `.github/workflows/deploy.yml` на пуш в `main`.

Сервер комнат — `.github/workflows/server.yml` на пуш в `main` с правкой `server/`, `src/poker/` или зависимостей: тесты, типы сервера, `npm run server:deploy` (`wrangler deploy`); нет секретов `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` — выкатка пропускается. В «Проверках PR» — `npm run server:check` (типы) и `npm run server:build` (`wrangler deploy --dry-run`).
