# Архитектура

Документ устройства — ядро и три части (Р-65). Здесь — модель данных, расчёт учёта, хранение, сборка и структура кода. Части: `02-Покер.md` — правила стола `src/poker/`, столы на устройстве и боты (`src/calc/`), сервер комнат; `02-Экраны-учёта.md` — ширина окна, игры, игроки, игра, казино-стол, настройки, импорт, справка; `02-Экраны-покера.md` — «Играть», стол на этом телефоне, против ботов, стол. Задача читает ядро и ту часть, которую трогает; описание изменённого — в своей части (шаг 5 исполнителя).

## Модель данных

```ts
type Game = {
  id: string            // ULID
  name: string          // «Пятница у Кирилла»; по умолчанию — дата
  date: string          // YYYY-MM-DD, день игры
  rate: number          // рублей за фишку: 0.5 — фишка по 50 копеек
  players: Player[]
  entries: Entry[]
  casino?: CasinoRound[] // раунды казино (Р-13); нет — казино не было
  mode?: 'poker' | 'mixed' | 'casino' // режим (Р-29): покер, покер и казино, только казино; нет — по данным
  closed?: boolean      // игра закрыта: записи не правятся без «Открыть снова»
  demo?: boolean        // демо-данные — удаляются одной кнопкой
  updatedAt: string     // ISO 8601
}

type Player = {
  id: string
  name: string          // копия имени на момент игры: правка постоянных её не трогает
  regularId?: string    // id постоянного игрока (Р-12); нет — гость
}

type Regular = { id: string; name: string } // постоянный игрок: id не меняется при переименовании (Р-12)

type Entry = {
  id: string
  playerId: string
  kind: 'buyin' | 'rebuy' | 'cashout'
  chips: number         // целое, > 0
  at: string            // ISO 8601, ставится само
}

type CasinoRound = {    // раунд казино (Р-13): сумма долей — ноль
  id: string
  amounts: { playerId: string; kopecks: number }[] // доля участника в копейках, целое, не 0
  at: string            // ISO 8601, ставится само
}

type Settings = {
  defaultRate: number     // курс новой игры; по умолчанию 0.5
  players?: Regular[]     // постоянные игроки — отмечены в новой игре (Р-07, Р-12); нет — пусто
  quickAmounts?: number[] // быстрые суммы у «Закуп», «Докуп», «Выход» (Р-07); нет — [500, 1000, 2000]
  compareWindow?: number  // окно сравнения на карточке игрока (Р-15): целое 3–10; нет или вне — 5
}
```

**Режим игры** (Р-29, `src/calc/gameMode.ts`): `gameMode` — поле `mode`, а нет его (игры до Р-29, игра из Телеграма, итог стола покера, демо) — по данным: раунды без покерных записей — `'casino'`, и то и другое — `'mixed'`, иначе — `'poker'`. «Новая игра» пишет выбранный режим (`createGame`, `NewGame.mode`, нет — `'poker'`); у `'casino'` записей нет, курс — из настроек. Смена — только `addCasino` («покер» → «покер и казино») и `addPoker` («только казино» → «покер и казино», курс — из настроек); обратно нет. Игра без поля при первой правке на экране игры получает режим по данным. Режим меняет только вид и создание игры: итоги, переводы и статистика считаются по записям и раундам, как раньше.

**Связь с постоянным игроком** (Р-12): `regularId` ставится при создании игры из отмеченных постоянных (по их id), при добавлении участника на экране игры и в игре из Телеграма — по точному совпадению имени (`linkRegulars`, `src/model.ts`); в игре из стола покера онлайн — по постоянному, под которым игрок сел (Р-20). Переименование постоянного меняет только `name` в настройках — id и связи прошлых игр остаются.

## Расчёт — `src/calc/`

- **Итог игрока:** `out − in`, где `in` — сумма закупов и докупов, `out` — сумма выходов (обычно один). В рублях — `× rate`, хранится и считается в копейках, округление — до копейки
- **Сходится ли игра:** сумма `in` всех = сумма `out` всех. Не сходится — итог показывает разницу словами и переводы не считает: «не хватает 500 фишек: у кого-то не записан выход»
- **Казино** (Р-13, `src/calc/casino.ts`): раунд вводится строками `Эрик, Артём +150` — каждый названный получает число в рублях, без знака — плюс; имя дважды — сложено (`parseRound`). Раунд добавляется, только если в ноль и все строки разобраны; имя не из игры — новый участник только казино (без покерных записей, связь с постоянным по имени). Три итога участника (`gameResult`): покер — копейки из фишек (`playerTotals`), казино — сумма долей, итого — их сумма. Игра сходится — покер сходится и все раунды в ноль; игра без закупов — только казино
- **Раунд казино с картами** (#76, Р-26, `src/calc/casinoDeal.ts`): вариант `DealKind` — `'holdem'` (`HOLDEM`, по 2 карты) или `'omaha'` (`OMAHA`, по 4) из `src/poker/cards.ts`; столы по `BOARD_CARDS` = 5 карт; по умолчанию `DEFAULT_TABLES` = 5 столов и ставка `DEFAULT_STAKE` = 100 ₽. Одна колода: карт — участники × карты руки + столы × 5 (`cardsUsed`), `maxTables` / `maxPlayers` — предел по колоде (холдем на 5 столах — до 13, омаха — до 6; омаха на 7 участников — до 4 столов). Раздача (`dealFromDeck`; `newDeal` — из `shuffle(buildDeck(...))` на Web Crypto): в руки по одной по кругу, затем столы по 5 подряд; меньше двух участников, повтор, ноль столов или карт не хватит — ошибка. Стол (`boardResult`) — победители `winners` в порядке участников, `bestHand().name` и у каждого победителя лучшая пятёрка (`best`, `bestHand().cards`, #96). Делёж (`roundShares`): банк = ставка × участников, поровну на столы (`tableParts`: копейки остатка — по одной первым столам), часть стола — его победителям поровну, остаток — по одной первым по порядку участников; у каждого `won` и `net` = `won` − ставка, сумма `net` — ноль. `sharesToRound` — раунд по именам (`ParsedRound`) для `addRound`: записанный раунд — обычный `CasinoRound`, нулевые доли не пишутся
- **Статистика постоянных игроков** (`src/calc/stats.ts`): только закрытые игры без `demo`, только участники с `regularId` из настроек (гости — нет); строка — по id постоянного, имя — из настроек. Итоги — покер, казино и итого (Р-13); итог в рублях — сумма копеек «итого» по играм (у каждой свой курс); игр и в плюсе; лучший и худший вечер — по рублям «итого»; докупы — число записей `rebuy`, среднее за игру. Порядок — по рублям, сверху самый большой плюс, без игр — внизу
- **Динамика игрока** (`src/calc/trend.ts`, `playerTrend`): те же закрытые игры без `demo`, в которых есть участник с этим `regularId` (дважды в игре — один вечер), новые первыми — как на «Играх» (дата, затем `id`). Окно N — `Settings.compareWindow` (Р-15). Окна — последние N и предыдущие до N, по «итого»: итог в копейках, в плюсе, средний итог за игру (целые копейки), докупов в среднем. Разница последних с предыдущими по каждому показателю; предыдущих меньше N — итог и «в плюсе» предыдущих приводятся к числу последних (по средним); лучше — больше, для докупов — меньше
- **Лучший и худший промежуток** (Р-15, `src/calc/trend.ts`, `playerSpans`): те же вечера игрока в порядке дат (старые первыми); скользящее окно из N вечеров подряд — сумма «итого» в копейках, день первой и последней игры. Лучший — наибольшая сумма, худший — наименьшая; могут пересекаться; при равенстве — более поздний. Вечеров меньше 2N — промежутков нет, есть число вечеров
- **Покер за всё время** (Р-55, #164, `src/calc/pokerAllTime.ts`, `allTimeHud`): счётчики `HudCounts` постоянного по всем записям хранилища `hands` (`allHands`) — сумма `addHand({}, раздача, итог)` по его месту в каждой раздаче, тот же подсчёт, что HUD вечера за столом, и с #241 — те же 3-бет, фолд на 3-бет, WTSD, W$SD и bb/100. Итог (`HudEnd`): взявшие банк — `pots[].winners` записи; итог в фишках — только у постоянного, `handNet` из `src/calc/handResult.ts` (выплаты минус вложенное, и у `live`: блайнды — `EveningTable`, в турнире неизвестны — раздача в bb/100 не идёт). Раздача для `addHand` (`HudHand` в `src/poker/hud.ts` — что он читает: места, кнопка, большой блайнд, ходы, круги торгов игры) — из `record` (карты на телефонах) или `live` (живые карты; большой блайнд — `EveningTable.bb`, в турнире — стартовый). Место постоянного — имя равно имени постоянного и это не гость: есть в `EveningTable.regulars`; у записей до Р-55 — только по имени, а двое с этим именем в одной раздаче — раздача не в счёт. Удалённый вечер — его записей нет, они не в счёте. Показ — `countsView` (`src/calc/pokerView.ts`, его же зовёт `hudView` стола): раздач нет — `null`, меньше `HUD_FEW_HANDS` — `few`
  - **Лучшие и худшие раздачи** (#197, `allTimeMore` там же; его 3-бет, WTSD, W$SD и bb/100 с #241 считает `allTimeHud` — полей `threeBet`, `wtsd`, `wsd`, `bb` больше нет): только записи с `record`, место — тем же `seatOf`. `AllTimeMore`: `hands` — раздач с записью, `best`, `worst`. Итог раздачи (`handNet`) — `payouts` минус вложенное: анте (`log`, `type: 'ante'`), блайнды (в `log` их нет: малый и большой — по `button`, хедз-ап — кнопка ставит малый, не больше стека после анте), на каждой улице — `bet` последнего хода игрока (до флопа без хода — блайнд); непокрытая часть самой большой суммы — хозяину, если он не сбросил (как `closeBetting`); докупы не в счёт. `best` / `worst` — до трёх раздач в плюсе и в минусе по ББ (`HandOutcome`: вечер, номер, фишки, ББ), при равных — более поздняя. Показ — `moreView` (`MoreView`: `best`, `worst`): раздач с записью нет — `null`; раздача — день и название вечера (`eveningDay`, `eveningName`), итог `formatBB` со знаком
- **Переводы:** жадно — самый большой должник платит самому большому получателю, пока все не на нуле. Переводов не больше «игроков с ненулевым итогом − 1». Проверка в тестах — пример со скриншота: 6 игроков, 5 переводов. Без казино — в фишках, рубли из фишек; с казино — по «итого» в копейках (Р-13): при дробном курсе сумма копеек покера может отличаться от нуля на копейку — она остаётся без перевода
- **Итог стола покера онлайн → игра** (Р-20, `src/calc/pokerGame.ts`, `gameFromTable`): из стола на момент конца — название и дата (сегодня), курс из настроек ведущего. Участники — по порядку посадки: сидящие — имя и `regularId` из стола, ушедшие — из записи `leave` (нет имени — «Ушёл со стола»); постоянный, севший снова, — тот же участник; гость — без `regularId`. Записи по журналу фишек: закуп — `buyin`, докуп — `rebuy` (`to − from`), уход — `cashout` с остатком; в конце — `cashout` каждому сидящему со стеком. Раздача не доиграна — отменяется: у сидящих стек до неё, ушедшему из неё возвращается поставленное, докуп, одобренный в ней, — `rebuy` и в стек. Правка стека записей не даёт — фишки могут не сойтись. Ноль фишек — без `cashout`. Сходится — игра `closed`, иначе открыта
- **Итог турнира → игра** (#78, Р-28, `src/calc/pokerGame.ts`, `gameFromTournament`): та же модель `Game`, курс `TOURNAMENT_RATE` = 1 (фишка игры — рубль). Название «Турнир ДД.ММ.ГГГГ», дата — сегодня. Участники — `tournament.entrants` по местам за столом (имя и `regularId` — из стола или из записи `leave`). Записи: каждому вход — `buyin` на бай-ин (`settings.tournament.buyIn`, время — старт турнира), каждый ребай (`rebuy` в журнале фишек) — `rebuy` на бай-ин, приз — `cashout` по месту (`standings`): фонд — все бай-ины (`prizePool`), проценты — `tournament.prizes`, рубли — вниз, остаток — первому месту (`prizeAmounts`); ноль — без `cashout`. Итог каждого = приз − все его бай-ины, игра в ноль — `closed`. На экране — `tournamentResults`: место, имя, бай-инов, приз, итог
- **Форма «Кэш» / «Турнир»** (#78, `src/calc/tournamentForm.ts`): `TournamentForm` — поля строками; `tournamentForm(players)` — сначала кэш, анте 0, турнир — `DEFAULT_TOURNAMENT`, свои призы — по числу игроков; `formSettings` — `format`, `ante`, `tournament` для настроек стола, ошибка — словами стола (`tournamentError`, `prizesError`); пустое поле — 0. `levelText` — «10/20, анте 2», `prizeRuleText` — правило призов словами из `PRIZE_RULES`
- **Тренажёр: эквити и диапазоны** (Р-73, #212; только безлимитный холдем; экран — #213, `02-Экраны-покера.md`, «Тренажёр»):
  - **Диапазон текстом** (`src/calc/rangeText.ts`): диапазон — веса 169 классов от 0 до 1 (`number[]`) в порядке сетки 13 × 13 `CLASSES` — строка по старшей карте от туза, на диагонали пары, выше — одномастные (`AKs`), ниже — разномастные (`AKo`); `classIndex`, `emptyRange`, `fullRange`. `parseRange(text)` → `{ weights }` или `{ error, piece }` (кусок не разобран или вес вне 0…1 — словами с этим куском). Куски — через запятую, пробел или `;`, буквы любые: класс (`AK` — обе масти), `+` (у пары — эта и старше, у `A9s+` — кикер до ранга под старшей), отрезок одной старшей карты и масти или пар (`KTs-K8s`, `22-55` — в любом порядке), вес `:0.5`; класс дважды — побеждает последний кусок; пусто — пустой диапазон. `rangeText(weights)` — короткая обратная запись: по весам (сначала 1, затем по убыванию), в весе — пары (`77+`, `55-22`), затем по старшей карте отрезки кикеров (`AJo+`, `AQs-A9s`; одинаковые у обеих мастей — без буквы, `A2+`); `parseRange` разбирает её в те же веса. Формата `[50]AKs[/50]` нет
  - **Эквити** (`src/calc/rangeEquity.ts`, `rangeEquity(sides, board, samples = SAMPLES)`): сторона `EquitySide` — `{ cards }` (конкретная рука, 2 карты) или `{ range }` (веса); сторон 2…6, борд — 0, 3, 4 или 5 карт, досдача — до 5. Сочетания стороны — `COMBOS` (`botRanges`) класса с весом больше 0 без карт борда и конкретных рук; раскладка — по сочетанию у каждой стороны без общих карт, её вес — произведение весов. Сила — `handScore`; выигрыш — вся досдача, ничья на k — по 1/k. Раскладок × досдач не больше `samples` (на борде из 5 карт — раскладок не больше `RIVER_EXACT` = 3 000 000, сила сочетания — один раз) — полный перебор, `exact: true`; иначе — `samples` досдач выборкой: у каждой стороны сочетание по весам, раскладка с общими картами отбрасывается (попыток — до `samples` × 200), зерно — `hash` входа, генератор `random` (вынесены из `allInOdds`). Ответ `RangeEquity`: `{ ok: true, exact, runs, sides: { share, win, tie }[] }` — доля банка, доля раскладок, где сторона выиграла одна и поделила банк, `runs` — досдач; или `{ ok: false, reason }` словами: сторон не 2…6, борд не тот, в руке не 2 карты, не карта, карта дважды, веса не 169 или вне 0…1, пустой диапазон (после карт борда и рук), нет ни одной раскладки без общих карт
  - **Вид экрана** (#213, `src/calc/trainerView.ts`): сторона `TrainerSide` — `{ mode: 'hand' | 'range', cards, range }` (рука и диапазон хранятся оба, переключение их не стирает); `TRAINER_SIDES_MIN` = 2, `TRAINER_SIDES_MAX` = 6, вес касания `TRAINER_WEIGHTS` — 1, 0,75, 0,5, 0,25, 0 (`weightLabel` — «100 %»). `trainerInput(sides, board)` — вход `rangeEquity` или причина словами: на борде одна-две карты, в руке меньше двух карт, диапазон без веса. `rangeSize` / `rangeSizeText` — сочетаний с весом (пара — 6, одномастные — 4, разномастные — 12) и доля от 1326 рук: «7,8 % рук · 104 сочетания». `takenCards` — карты рук других сторон и борда (диапазон карт не занимает), `pickCard` — касание карты: снять выбранную, добавить, в полном ряду заменить последнюю. `TRAINER_DECK` — колода выбора, ряд на масть от туза. Ответ: `shareText` — «62,3 %», `winTieText` — «победа … · ничья …», `runsText` — «≈, N досдач» (выборка), «точно, N досдач» (перебор), «точно, без досдачи» (борд из 5 карт)
  - **Раздача из истории — в калькулятор** (#221, `src/calc/trainerFromHand.ts`): `trainerStart(saved: SavedHand)` → `TrainerStart` `{ sides: (Card[] | null)[], board }` (сторона — две карты или `null` — пустой диапазон) или `null` — не холдем (`record.game.id !== 'holdem'`) или живые карты. Запись — в «моём виде» `handFor(hand, table.me)`. Я (`table.me` за столом) — первым, если карты известны: `mine`, иначе `hidden` у меня, иначе `shown` у меня; не знаем, кто я, или карт нет — моей стороны нет. Соперники по местам от кнопки (следующий за ней первым): вскрытые (`shown`, все карты не `null`) — рукой, даже сбросившие; не сбросившие (ход `fold` в `log`) без вскрытия — `null`. Сторон меньше двух — `null` за каждого сбросившего на последней улице `log`; всё равно меньше — `null` до двух. Больше 6 — первые 6 (я, вскрытые, пустые). Борд — `record.board`, при `runs` — общая часть бордов. Адрес: `trainerHash` — `#/poker/trainer?side=AsKs&side=&side=QhQd&board=Ah7d2c`, `trainerHashOf(saved)` — адрес или `null`; `parseTrainerPath(путь)` — обратно: без `side` — `null` (чистый лист), кривое (карта не из колоды, повтор, сторона не из двух карт, сторон больше 6, борд не из 0/3/4/5 карт, борд дважды) — `null`; одна сторона — вторая `null`. Ничего не хранится: формат записей раздач не меняется

## Хранение

IndexedDB, база `magic_fishki`, версия 6: хранилища `games` (ключ `id`), `settings` (одна запись), `hands` — раздачи прошлых вечеров покера, `charts` — свои чарты тренажёра, `dirty` и `syncMeta` — под синхронизацию (Р-105). Новая версия — шагом миграции, старые записи не теряются.

- **1** — хранилища `games` и `settings`
- **2** (Р-12) — `settings.players` из строк в `{ id, name }` с новыми id в прежнем порядке; участникам сохранённых игр с точно тем же именем — `regularId`; остальные поля игр, в том числе `updatedAt`, не меняются. Другая вкладка на версии 1 закрывает базу по `onversionchange`
- **3** (Р-37, #114) — новое пустое хранилище `hands`; игры и настройки не трогаются
- **4** (Р-77, #215) — новое пустое хранилище `charts` (ключ `id`); игры, настройки и раздачи не трогаются
- **5** (Р-105, #264) — новые пустые хранилища `dirty` (ключ `['store', 'key']`) и `syncMeta` (ключ — имя); раздачам без `updatedAt` — начало их вечера (`startedAt` в ISO); игры, настройки и чарты не трогаются
- **6** (Р-106, #301) — помеченные `deleted: true` игры, раздачи и чарты сжимаются до меток (ключ, `deleted`, `updatedAt` — прежний); живые записи, `dirty` и `syncMeta` не трогаются

**Под синхронизацию** (Р-105, #264; шаг 2 — сама синхронизация) — синхронизируется то же, что входит в файл-копию; демо-игры (`demo: true`) — никогда. У каждой записи — время правки `updatedAt` (ISO): у игр и чартов — как было, у раздач (`SavedHand.updatedAt`) — с версии 5, у записи настроек — поле `updatedAt` рядом с `Settings` (ставит `saveSettings`; `getSettings` его не отдаёт, `settingsWithDefaults` берёт только поля настроек; до первой записи после миграции его нет). **Удаление — меткой** (Р-106, #301): `deleteGame`, `deleteEvening`, `deleteEvenings`, `deleteChart` пишут вместо записи метку — только ключ, `deleted: true` и новый `updatedAt`: `Tombstone` `{ id, deleted, updatedAt }` у игр и чартов, `HandTombstone` `{ evening, number, deleted, updatedAt }` у раздач (`src/store/db.ts`); содержимое (карты, ходы, имена, суммы, диапазоны) стёрто. Уже удалённое второй раз не трогается и в счёт `deleteEvenings` не идёт. Все чтения (`listGames`, `getGame`, `allHands`, `eveningRecords`, `handKeys`, `listEvenings`, `eveningHands`, `listCharts`, `chartIds`) метки пропускают — в копию они не попадают, для человека удаление окончательное, с тем же вопросом. Демо-игра стирается совсем, без метки (`deleteGame` и `deleteDemoGames`). **Метка живёт `TOMBSTONE_DAYS` = 30 дней** по `updatedAt`, потом стирается совсем — при открытии базы, до первого чтения, одной транзакцией (`purgeTombstones`; ошибка чистки работе не мешает): синхронизация не подключалась (`syncMeta` пуст) — стирается метка старше 30 дней и её отметка в `dirty`; подключалась — только метка старше 30 дней, которой нет в `dirty` (уже отправлена): неотправленное удаление не теряется. Новых отметок чистка не ставит. **Восстановление** (`restoreGames`, `restoreHands`, `restoreCharts`): запись с ключом метки — встаёт целиком из копии вместо метки, `updatedAt` — сейчас; иначе (и когда метка уже стёрта) — как есть, со своим `updatedAt` (раздача из копии до #264 без него — начало вечера); живые с тем же ключом отсеивает `planRestore`, как прежде. `saveGame`, `saveChart` заменяют метку с тем же ключом. `saveHands`: изменённая или новая раздача — новый `updatedAt` («Показать» после вскрытия, после паса и мака — тоже), та же самая (без учёта `updatedAt`) — не переписывается; `mine` берётся только у живой прежней записи, метка заменяется записью. **`dirty`** — что изменилось и ещё не отправлено, `DirtyMark` `{ store: 'games' | 'settings' | 'hands' | 'charts' | 'local', key }`: ключ записи (у раздач — `[evening, number]`, у настроек — `'settings'`, у `local` — ключ localStorage); одна отметка на запись. Ставят той же транзакцией `saveGame`, `saveSettings`, `saveHands`, `saveChart`, восстановление и метка удаления (у демо — нет); `listDirty`, `clearDirty(marks)` — для шага 2. **`syncMeta`** — память синхронизации по имени (отпечатки файлов, последний коммит): `loadSyncMeta(key)`, `saveSyncMeta(key, value)`. `dirty` и `syncMeta` — этого устройства: не синхронизируются и в копию не входят. **Память браузера:** ключи, что входят в копию (`fishki.poker.notes`, `noteLabels`, `look`, `ownGames`, `quickRoom`, `bigBlinds`, `quickBets`, `tableSize`, `dockSize`, `betStep` и `fishki.theme`), при смене значения (стирание — тоже) получают время правки в `fishki.sync.stamps` (`{ ключ: ISO }`, `loadSyncStamps`) и отметку `local` в `dirty` сразу после записи (`stampSynced` в `src/screens/pokerStorage.ts`; `write` — только если значение другое, гамма — `saveTheme`); слияние на шаге 2 — по ключу целиком, позднее побеждает. Остальные ключи (пароль и адрес сервера, места, «последняя игра», своя рубашка, звук, HUD и прочее) — этого устройства, не синхронизируются.

**Раздачи прошлых вечеров** (`hands`, Р-37) — запись на раздачу `SavedHand` (`src/calc/evenings.ts`): `{ evening, code, startedAt, number, hand }`, ключ — `[evening, number]`, индекс `evening`; `hand` — `HistoryHand` (`src/poker/history.ts`) как пришла за столом: у онлайн-стола — вид этого игрока (`handFor`: свои карты взявшего без вскрытия — только у него). С Р-54 (#163): у записи ещё необязательные `table` — `EveningTable` `{ me, game, limit, sb, bb, ante, maxSeats, tournament, regulars? }` (`eveningTable`: игрок этого телефона — `null` у стола на одном телефоне — и игра стола, для выгрузки; блайнды — для живых карт, у которых в раздаче их нет; `regulars` — с Р-55 (#164): постоянные стола, id игрока за столом → `regularId`, сидящие и ушедшие по записи ухода, кого нет — гость; у записей до Р-55 поля нет) и `mine` — свои карты этого телефона в раздаче (`useMyCards` запоминает их по номеру, пока раздача идёт: у записей до #278 карт сбросивших нет, с #278 они в `hidden` — только своему телефону); у записей до Р-54 полей нет, хранилище и версия базы те же. `saveHands` без `mine` оставляет `mine` прежней записи. Против ботов — свой вечер `bots-id стола с ботами` (`botsEvening`, `isBotsEvening`; строка — «Против ботов»), раздачи пишутся по ходу тем же `useHandCopy` из `bots.history` в виде человека (`handFor`); «Закончить» их не стирает. `eveningRecords` — записи вечера целиком, `allHands` — все записи, `handKeys` — ключи, `restoreHands` — запись из копии одной транзакцией. **Выгрузка** (`src/calc/handText.ts`): `handsText` — раздачи текстом истории покер-румов (шапка `PokerStars Hand #<начало вечера, с><номер, 4 знака>: <игра> <лимит> (sb/bb) - <дата начала вечера>`, стол и кнопка, места и стеки, анте и блайнды — по местам от кнопки, `Dealt to` — свои карты (`mine`, иначе взятые без вскрытия или вскрытые), ходы по улицам с суммами прибавки, борд, непокрытая ставка, вскрытие, `collected`, `*** SUMMARY ***`); вечера — по началу, в вечере — по номеру; чужие карты — только вскрытые и показанные. Файл — `fishki-hands-ГГГГ-ММ-ДД.txt` («Выгрузить» у вечера, день вечера), `fishki-hands-all-ГГГГ-ММ-ДД.txt` («Выгрузить все», сегодня). Входят в файл-копию с формата 3.

## Синхронизация

Р-105, Р-106, Р-107, #265 — свои данные между своими устройствами через приватный репо данных на GitHub. Механика — копия из `FamilyCore@d9e5ec6`, правится здесь (шапка каждого файла — «Копия из FamilyCore@d9e5ec6»; исправления ядра сами не приходят — сверка при его крупных правках): `src/sync/github.ts` (клиент GitHub через `fetch`; своё — удаление файла коммитом, запись дерева с `sha: null`), `token.ts` (`WARN_DAYS` = 30, `expiryDay`), `dates.ts` (нужное из дат ядра), `sync.ts` (проход и расписание), `access.ts` (слова «Проверить доступ»; своё — публичный репо — ошибка), `syncDot.ts` (точка состояния); экран — `src/screens/SyncSettings.tsx`. Из ядра не взяты: срез итогов `summary.json`, общая база `family` и `moveToFamily`, демо-база, `AppConfig`, `createDb`, `meta.json`.

- **Что синхронизируется** — то же, что в файле-копии: игры (кроме `demo: true`), запись настроек, раздачи прошлых вечеров, свои чарты, ключи памяти браузера из копии (`SYNCED_KEYS` в `pokerStorage.ts`; своя рубашка `fishki.poker.ownBack` и своя аватарка `fishki.poker.avatar` — нет). Не синхронизируются: стол, который идёт (localStorage стола), `dirty`, `syncMeta`, токен и имя репо, устройственное.
- **Раскладка** (`src/sync/layout.ts`): `games/<год>.json` — игры по году `date`, метка удаления (`Tombstone`, без `date`) — по году её `updatedAt`; `hands/<вечер>.json` — раздачи вечера одним файлом (имя — `encodeURIComponent(evening)`); `charts.json`; `settings.json` — запись настроек; `prefs.json` — `{ key, value, updatedAt }` (`value` — строка localStorage или `null` — стёрт; время — `fishki.sync.stamps`, ключ без времени — с начала отсчёта); `README.md` — что это и что руками не править, кладётся, только если его нет. Файл — `{ app: 'magic_fishki', kind, format: SYNC_FORMAT (1), records }`, записи по ключу (`recordKey`; у раздачи — `[evening, number]`), JSON с отступом и переводом строки в конце: одинаковые данные — одинаковый отпечаток. Чарты и `prefs.json` — файлом всегда; вечер и год без записей файла не дают. `parseFile`: не JSON, чужое `app`/`kind` — ошибка, `format` новее — «Обнови приложение»; запись без ключа или `updatedAt` — мимо. Метки старше `TOMBSTONE_DAYS` в файлы не идут (`expiredMark`).
- **Проход** (`runSync`, как у ядра, шапка `sync.ts`): голова ветки и дерево; скачать свои файлы, чей отпечаток разошёлся с запомненным (`planDownload`; первое подключение — все свои); разобрать все, затем влить (порт `merge`); правило «нет в репо»; собрать файлы из базы (`buildFiles`); удалить из репо свои файлы, которых база больше не даёт (вечер без записей — так метки, истёкшие и стёртые из базы, уходят и из файлов); отправить одним коммитом разошедшееся и удалённое; снять отметки `dirty`, снятые до прохода (правки во время прохода уедут следующим). Пустой репо — первым коммитом `README.md` через Contents API. Гонка (ветка ушла вперёд) — три попытки с паузой 1 и 2 с, потом повтор через `RETRY_MS` = минута. Ошибка чтения обрывает проход до записи.
- **Слияние** — поздний `updatedAt` побеждает по ключу. База: `mergeRemote(store, records)` в `src/store/db.ts` — одной транзакцией; у здешней записи без `updatedAt` (настройки до первой записи) — пришедшая; демо-игра здесь не перезаписывается, пришедшая демо — мимо; пришедшая метка — только ключ, `deleted`, `updatedAt`; метка старше 30 дней не пишется, но если она позже здешней записи — та стирается совсем; отметок `dirty` слияние не ставит; изменилось — событие `remote`. Ключи браузера: `applySyncedPrefs` в `pokerStorage.ts` — по ключу целиком, мимо `stampSynced` (без отметки, время — пришедшее), копии в памяти страницы (заметки, вид стола, ББ, ставки, шаг, размеры) сбрасываются; пришла гамма — `applyTheme`.
- **«Нет в репо — значит удалено»** (уточнение 17.11, отступление от ядра): после слияния запись игр, раздач или чартов, которой нет ни в одном скачанном файле, а её файл в дереве отсутствует или скачан (изменился), и которая не в `dirty` (ни до прохода, ни сейчас), — удалена на другом устройстве, метка истекла: `forgetRecords` стирает её совсем (одной транзакцией; запись с отметкой в `dirty` остаётся), в репо она не уходит. Файл не скачан (не менялся с прошлого прохода) — запись в нём, как была. Первое подключение — правило не действует. Первое подключение — нет запомненного дерева **этого** репо и ветки: память `syncMeta` — `tree` `{ repo: 'владелец/имя#ветка', tree: { путь: sha }, commit }` и `lastAt`; другой репо или ветка — снова первое подключение.
- **Порт** `Ports` (`sync.ts`; настоящий — `src/sync/ports.ts`): `readAll` (`syncSnapshot` — игры без демо, запись настроек с `updatedAt`, раздачи, чарты, с метками; `syncedPrefs`), `merge`, `forget`, `listDirty`, `clearDirty`, `remembered`, `remember`. Ключ отметки `dirty` строкой — `dirtyKey` (`local` → `prefs`).
- **Когда** (`createSync`, один экземпляр — `src/sync/instance.ts`, запуск `startAutoSync` в `src/main.tsx`): не настроено (нет репо или токена) — ни одного запроса; правка (`onChange` из `db.ts`, `local`) — через `QUIET_MS` = 5 с тишины; возврат сети или вкладки — не чаще `MIN_GAP_MS` = раз в минуту; запуск приложения; «Синхронизировать сейчас». Второй вызов подхватывает идущий проход. Событие изменения `onChange(listener)` в `db.ts`: после каждой записи данных — `local`, после `mergeRemote`, `forgetRecords` и влитых ключей браузера (`announceRemote`) — `remote`; снятие отметок — без события.
- **Состояние** `SyncStatus` `{ state: off | idle | syncing | error, pending, lastAt, error, badToken, deferred, offline }`: нет связи (`GitHubError.status` 0) — не ошибка, `offline` («Ждёт сети»); гонка до конца — `deferred`. Экраны вне стола перечитывают влитое (`useRemoteVersion`): «Игры», игра, «Игроки», карточка игрока, «Прошлые вечера», «Мои чарты», «Настройки»; столы покера и казино — нет.
- **Настройка** — память браузера «Фишек» (`src/sync/config.ts`): `fishki.sync.repo`, `fishki.sync.token`, `fishki.sync.tokenExpires`, `fishki.sync.branch` (нет — `main`; поля на экране нет); не IndexedDB, не общая база соседних приложений на том же адресе, не файл-копия и не репо данных. Новый токен стирает срок прежнего; «Забыть токен» — токен и срок, имя репо остаётся. Срок — из заголовка ответа GitHub, иначе вписывается руками.
- **Экран** — «Настройки» → раздел «Синхронизация» (`sync` в `SETTINGS_GROUPS`, после «Копии данных»), описание — `02-Экраны-учёта.md`.

Из сети шрифтов нет, `preload` нет. GitHub Pages — `.github/workflows/deploy.yml` на пуш в `main`.

Сервер комнат — `.github/workflows/server.yml` на пуш в `main` с правкой `server/`, `src/poker/` или зависимостей: тесты, типы сервера, `npm run server:deploy` (`wrangler deploy`); нет секретов `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` — выкатка пропускается. В «Проверках PR» — `npm run server:check` (типы) и `npm run server:build` (`wrangler deploy --dry-run`).

  sync/       синхронизация через приватный репо данных (#265): копии ядра семьи — github, token, dates, sync, access, syncDot; своё — layout (раскладка), config (репо и токен), ports (порт к базе), instance (экземпляр и хуки) + тесты

server/       сервер комнат на Cloudflare: room, registry, http + тесты; index.ts — Worker и объекты; wrangler.toml
