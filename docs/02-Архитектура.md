# Архитектура

## Модель данных

```ts
type Game = {
  id: string            // ULID
  name: string          // «Пятница у Кирилла»; по умолчанию — дата
  date: string          // YYYY-MM-DD, день игры
  rate: number          // рублей за фишку: 0.5 — фишка по 50 копеек
  players: Player[]
  entries: Entry[]
  casino?: CasinoRound[] // раунды казино (Р-13); нет — казино не было
  mode?: 'poker' | 'mixed' | 'casino' // режим (Р-29): покер, покер и казино, только казино; нет — по данным
  closed?: boolean      // игра закрыта: записи не правятся без «Открыть снова»
  demo?: boolean        // демо-данные — удаляются одной кнопкой
  updatedAt: string     // ISO 8601
}

type Player = {
  id: string
  name: string          // копия имени на момент игры: правка постоянных её не трогает
  regularId?: string    // id постоянного игрока (Р-12); нет — гость
}

type Regular = { id: string; name: string } // постоянный игрок: id не меняется при переименовании (Р-12)

type Entry = {
  id: string
  playerId: string
  kind: 'buyin' | 'rebuy' | 'cashout'
  chips: number         // целое, > 0
  at: string            // ISO 8601, ставится само
}

type CasinoRound = {    // раунд казино (Р-13): сумма долей — ноль
  id: string
  amounts: { playerId: string; kopecks: number }[] // доля участника в копейках, целое, не 0
  at: string            // ISO 8601, ставится само
}

type Settings = {
  defaultRate: number     // курс новой игры; по умолчанию 0.5
  players?: Regular[]     // постоянные игроки — отмечены в новой игре (Р-07, Р-12); нет — пусто
  quickAmounts?: number[] // быстрые суммы у «Закуп», «Докуп», «Выход» (Р-07); нет — [500, 1000, 2000]
  compareWindow?: number  // окно сравнения на карточке игрока (Р-15): целое 3–10; нет или вне — 5
}
```

**Режим игры** (Р-29, `src/calc/gameMode.ts`): `gameMode` — поле `mode`, а нет его (игры до Р-29, игра из Телеграма, итог стола покера, демо) — по данным: раунды без покерных записей — `'casino'`, и то и другое — `'mixed'`, иначе — `'poker'`. «Новая игра» пишет выбранный режим (`createGame`, `NewGame.mode`, нет — `'poker'`); у `'casino'` записей нет, курс — из настроек. Смена — только `addCasino` («покер» → «покер и казино») и `addPoker` («только казино» → «покер и казино», курс — из настроек); обратно нет. Игра без поля при первой правке на экране игры получает режим по данным. Режим меняет только вид и создание игры: итоги, переводы и статистика считаются по записям и раундам, как раньше.

**Связь с постоянным игроком** (Р-12): `regularId` ставится при создании игры из отмеченных постоянных (по их id), при добавлении участника на экране игры и в игре из Телеграма — по точному совпадению имени (`linkRegulars`, `src/model.ts`); в игре из стола покера онлайн — по постоянному, под которым игрок сел (Р-20). Переименование постоянного меняет только `name` в настройках — id и связи прошлых игр остаются.

## Расчёт — `src/calc/`

- **Итог игрока:** `out − in`, где `in` — сумма закупов и докупов, `out` — сумма выходов (обычно один). В рублях — `× rate`, хранится и считается в копейках, округление — до копейки
- **Сходится ли игра:** сумма `in` всех = сумма `out` всех. Не сходится — итог показывает разницу словами и переводы не считает: «не хватает 500 фишек: у кого-то не записан выход»
- **Казино** (Р-13, `src/calc/casino.ts`): раунд вводится строками `Эрик, Артём +150` — каждый названный получает число в рублях, без знака — плюс; имя дважды — сложено (`parseRound`). Раунд добавляется, только если в ноль и все строки разобраны; имя не из игры — новый участник только казино (без покерных записей, связь с постоянным по имени). Три итога участника (`gameResult`): покер — копейки из фишек (`playerTotals`), казино — сумма долей, итого — их сумма. Игра сходится — покер сходится и все раунды в ноль; игра без закупов — только казино
- **Раунд казино с картами** (#76, Р-26, `src/calc/casinoDeal.ts`): вариант `DealKind` — `'holdem'` (`HOLDEM`, по 2 карты) или `'omaha'` (`OMAHA`, по 4) из `src/poker/cards.ts`; столы по `BOARD_CARDS` = 5 карт; по умолчанию `DEFAULT_TABLES` = 5 столов и ставка `DEFAULT_STAKE` = 100 ₽. Одна колода: карт — участники × карты руки + столы × 5 (`cardsUsed`), `maxTables` / `maxPlayers` — предел по колоде (холдем на 5 столах — до 13, омаха — до 6; омаха на 7 участников — до 4 столов). Раздача (`dealFromDeck`; `newDeal` — из `shuffle(buildDeck(...))` на Web Crypto): в руки по одной по кругу, затем столы по 5 подряд; меньше двух участников, повтор, ноль столов или карт не хватит — ошибка. Стол (`boardResult`) — победители `winners` в порядке участников, `bestHand().name` и у каждого победителя лучшая пятёрка (`best`, `bestHand().cards`, #96). Делёж (`roundShares`): банк = ставка × участников, поровну на столы (`tableParts`: копейки остатка — по одной первым столам), часть стола — его победителям поровну, остаток — по одной первым по порядку участников; у каждого `won` и `net` = `won` − ставка, сумма `net` — ноль. `sharesToRound` — раунд по именам (`ParsedRound`) для `addRound`: записанный раунд — обычный `CasinoRound`, нулевые доли не пишутся
- **Статистика постоянных игроков** (`src/calc/stats.ts`): только закрытые игры без `demo`, только участники с `regularId` из настроек (гости — нет); строка — по id постоянного, имя — из настроек. Итоги — покер, казино и итого (Р-13); итог в рублях — сумма копеек «итого» по играм (у каждой свой курс); игр и в плюсе; лучший и худший вечер — по рублям «итого»; докупы — число записей `rebuy`, среднее за игру. Порядок — по рублям, сверху самый большой плюс, без игр — внизу
- **Динамика игрока** (`src/calc/trend.ts`, `playerTrend`): те же закрытые игры без `demo`, в которых есть участник с этим `regularId` (дважды в игре — один вечер), новые первыми — как на «Играх» (дата, затем `id`). Окно N — `Settings.compareWindow` (Р-15). Окна — последние N и предыдущие до N, по «итого»: итог в копейках, в плюсе, средний итог за игру (целые копейки), докупов в среднем. Разница последних с предыдущими по каждому показателю; предыдущих меньше N — итог и «в плюсе» предыдущих приводятся к числу последних (по средним); лучше — больше, для докупов — меньше
- **Лучший и худший промежуток** (Р-15, `src/calc/trend.ts`, `playerSpans`): те же вечера игрока в порядке дат (старые первыми); скользящее окно из N вечеров подряд — сумма «итого» в копейках, день первой и последней игры. Лучший — наибольшая сумма, худший — наименьшая; могут пересекаться; при равенстве — более поздний. Вечеров меньше 2N — промежутков нет, есть число вечеров
- **Переводы:** жадно — самый большой должник платит самому большому получателю, пока все не на нуле. Переводов не больше «игроков с ненулевым итогом − 1». Проверка в тестах — пример со скриншота: 6 игроков, 5 переводов. Без казино — в фишках, рубли из фишек; с казино — по «итого» в копейках (Р-13): при дробном курсе сумма копеек покера может отличаться от нуля на копейку — она остаётся без перевода
- **Итог стола покера онлайн → игра** (Р-20, `src/calc/pokerGame.ts`, `gameFromTable`): из стола на момент конца — название и дата (сегодня), курс из настроек ведущего. Участники — по порядку посадки: сидящие — имя и `regularId` из стола, ушедшие — из записи `leave` (нет имени — «Ушёл со стола»); постоянный, севший снова, — тот же участник; гость — без `regularId`. Записи по журналу фишек: закуп — `buyin`, докуп — `rebuy` (`to − from`), уход — `cashout` с остатком; в конце — `cashout` каждому сидящему со стеком. Раздача не доиграна — отменяется: у сидящих стек до неё, ушедшему из неё возвращается поставленное, докуп, одобренный в ней, — `rebuy` и в стек. Правка стека записей не даёт — фишки могут не сойтись. Ноль фишек — без `cashout`. Сходится — игра `closed`, иначе открыта
- **Итог турнира → игра** (#78, Р-28, `src/calc/pokerGame.ts`, `gameFromTournament`): та же модель `Game`, курс `TOURNAMENT_RATE` = 1 (фишка игры — рубль). Название «Турнир ДД.ММ.ГГГГ», дата — сегодня. Участники — `tournament.entrants` по местам за столом (имя и `regularId` — из стола или из записи `leave`). Записи: каждому вход — `buyin` на бай-ин (`settings.tournament.buyIn`, время — старт турнира), каждый ребай (`rebuy` в журнале фишек) — `rebuy` на бай-ин, приз — `cashout` по месту (`standings`): фонд — все бай-ины (`prizePool`), проценты — `tournament.prizes`, рубли — вниз, остаток — первому месту (`prizeAmounts`); ноль — без `cashout`. Итог каждого = приз − все его бай-ины, игра в ноль — `closed`. На экране — `tournamentResults`: место, имя, бай-инов, приз, итог
- **Форма «Кэш» / «Турнир»** (#78, `src/calc/tournamentForm.ts`): `TournamentForm` — поля строками; `tournamentForm(players)` — сначала кэш, анте 0, турнир — `DEFAULT_TOURNAMENT`, свои призы — по числу игроков; `formSettings` — `format`, `ante`, `tournament` для настроек стола, ошибка — словами стола (`tournamentError`, `prizesError`); пустое поле — 0. `levelText` — «10/20, анте 2», `prizeRuleText` — правило призов словами из `PRIZE_RULES`
- **Стол на одном телефоне** (Р-21, `src/calc/localTable.ts`): тот же `TableState` и `handle` из `src/poker/`, только сообщения шлёт экран, а не сервер; от чьего имени — решается здесь. `LocalTable` — `{ id, table, gameId }`: свой id стола (`ulid()` при «Начать») и id записанной игры (`null` — не записана). `startLocalTable` — от 2 до `LOCAL_MAX_SEATS` = 10 игроков (`localStartError`), садятся по порядку, ведущий по правилам — первый, `maxSeats` — 10 (место новым); `actFor` — ход от того, чья очередь (`toActId`); `hostDo` — команда от `hostId`; `rebuyNow` — докуп сразу: `rebuy` от игрока и `rebuyAnswer` с «да» от ведущего (в раздаче — в стек после неё, `pendingRebuy`); `seatPlayer` — новый игрок; `removePlayer` — ведущего: сначала `passHost` следующему по месту, затем `remove`, отказ — стол как был; `localTableView` — `tableView` от ведущего, кнопки хода — того, чей ход (`actionsView`), «меня» за столом нет; `parseLocalTable` — стол из памяти устройства, не похоже — `null`. `online` у игроков — `true` с посадки, `setOnline` не зовётся; таймера хода, перерыва и раздачи «сама» нет — настройки времени по умолчанию (выкл), `onTime` не зовётся (#75). Турнир и анте (#78): `startLocalTable` берёт ещё `ante`, `format` и `tournament`; `tournamentRebuyFor` — «Ребай» от имени выбывшего; «Перерыв» (`pause` через `hostDo`) — только в турнире, часы уровней — по часам телефона; ожидание ребая (#94) закрывает экран раз в секунду (`closeRebuyWait` вместо будильника), «Закончить турнир» — `endTournament` через `hostDo`
- **Бот покера** (#117, Р-38, `src/calc/bot.ts`): `botMove(view, botId, level, random)` — чистая функция: вход — вид стола глазами бота (`viewFor`), выход — допустимый ход (`BetAction`; не его ход — `null`). Читает только свои карты, общие, открытые всем карты соперников (`publicCards`), банк (`committed` всех), ставку и позицию — подай ему весь стол, ответ тот же (тест). Кнопки хода — `actionsView`: намерение «пас / колл / повысить до N» превращается в допустимый ход — пас при возможном чеке — чек; повысить нельзя — олл-ин, если есть, иначе колл; сумма — от `raise.min` до `raise.max`, весь стек — `allin`. Сила: до флопа — счёт Чена по двум старшим картам (`preflopStrength`, 0 — 7-2 разной масти, 1 — пара тузов); с флопа — доля банка против случайных рук соперников (не больше 3), `BOT_SAMPLES` = 60 досдач из колоды без своих, общих и открытых карт; рука — `handScore` из `allInOdds.ts` (лучшая пятёрка числом по правилам варианта, как `compareHands` у `bestHand`; пятёрки номерами — в памяти модуля на каждый размер руки и стола). Позиция — 1 у кнопки, 0,4 у блайндов, остальные — по порядку хода до флопа. Уровни (`BotLevel`, `BOT_LEVELS`): «Новичок» (`novice`) — шум ±0,15, почти всё уравнивает, пас — по слабости руки и доле стека, повышает редко и только сильной; «Любитель» (`amateur`) — шум ±0,1, открытие 3 ББ с силы выше 0,5 − 0,1 × позиция, после флопа колл по цене банка; «Сильный» (`strong`) — шум ±0,05, диапазон по позиции (`0,55 − 0,3 × позиция`), открытие 2,5 ББ и по ББ за уравнявших, 3-бет втрое, иногда кража с поздней позиции; после флопа ставка 2/3 банка с силой, блеф 1/2 банка с позиции, повышение на банк, колл — по цене банка. Случай — `random` (`Random`, 0…1); для тестов — `seededRandom(seed)` (mulberry32)
- **Стол против ботов** (#117, Р-38, `src/calc/botTable.ts`): тот же `TableState` и `handle`, что у комнаты и стола на одном телефоне. `BotTable` — `{ id, table, meId, level, open, history }`: весь стол (с колодой и картами ботов), я — `meId` и ведущий, уровень всех ботов, «Карты ботов открыты», раздачи вечера. `startBotTable(form)` — от `BOTS_MIN` = 1 до `BOTS_MAX` = 5 ботов (`botCountError`; в форме сначала `BOTS_DEFAULT` = 3, «Любитель»): я первым под именем «Вы», боты по порядку «Бот Север», «Бот Юг»…; `maxSeats` — ботов + 1, карты `phones`, холдем, кэш. `dealBotHand` — «Начать раздачу»: колоду тасует телефон (`shuffle(deckFor(game))`, как сервер) и подаёт в `handle` со `start`; мои фишки кончились (`iAmBroke`) — отказ. `myMove` — мой ход (не моя очередь — отказ), `botStep` — ход того бота, чья очередь (`botToAct`), решением `botMove` по `viewFor(table, бот)`; `myRebuy` — мне стартовый стек (`rebuyNow`). После каждого шага между раздачами боты без фишек докупаются сами на стартовый стек; окончилась раздача — в `history` (`finishedHand`, `keepHand`). `botTableView` — `tableView` по `viewFor(table, я)`; «открыты» — у ботов в раздаче (не сбросивших) карты лицом, только в виде экрана. `parseBotTable` — стол из памяти устройства (`parseLocalTable` и `meId` среди игроков, уровень из списка), не похоже — `null`
- Всё — чистые функции с тестами

## Покер через интернет — `src/poker/` (Р-14, Р-17)

Этап 1 — кэш-игра в холдем «живые карты, цифровые фишки»: карты настоящие, ставки, банки, очередь хода и стеки ведёт программа. Этап 2 (Р-23) — режим комнаты «карты на телефонах»: колоду тасует сервер комнаты, карты сдаёт и банки по силе руки раздаёт программа. Чистые функции без DOM, IndexedDB и модулей Node — их берут и сайт, и сервер комнат; время — параметром `now`, случайное — Web Crypto. Экран — «Покер онлайн» (Р-19, ниже в «Экранах»).

- **Стол** (`table.ts`, `TableState`) — обычный JSON: сервер сохраняет его между сообщениями и поднимает снова. У игрока за столом — `regularId`: постоянный игрок (Р-12), под которым он сел, или `null` — гость; под одним постоянным за столом сидит один («Этот игрок уже за столом»). `handle(state, from, message, now)` — новое состояние или отказ с причиной, состояние при отказе не меняется. Ведущий (`hostId`) — создатель стола; передаёт ведение сам, а вне сети дольше минуты (`setOnline`, `HOST_TAKEOVER_MS`) — его берёт любой игрок. Посадка — закуп `startingStack`; докуп — запрос игрока, «да» ведущего; во время раздачи — в стек после неё. Правка стека ведущим — только между раздачами. Место (`seat`, 0…`maxSeats − 1`) — при посадке первое свободное; пересадка (`moveSeat`, #98) — сам или ведущий за другого, только между раздачами и в «Перерыв» (в раздаче — «Пересесть можно между раздачами»), только на свободное (занято — «Место уже занято — выберите другое»: двое на одно — сел первый); фишек не стоит, кнопка следующей раздачи — к следующему по номеру месту от прошлой кнопки, без «мёртвой кнопки»: пересевший может пропустить или повторить блайнд. Убрать игрока ведущий может, если тот не в раздаче или уже сбросил карты; ещё в раздаче (в том числе ва-банк) — отказ «Игрок в раздаче — уберите после неё». Уходит с остатком: стек, а в раздаче — то, что не поставил, плюс одобренный в ней докуп. Журнал фишек (`chipLog`): закуп, докуп и правка — кто, было, стало; отказ в докупе; уход (`leave`) — кто убрал, остаток, имя и `regularId` ушедшего (у записей до #60 имени нет). Режим карт — `settings.cards`: `'live'` (по умолчанию) или `'phones'`; у столов до этапа 2 поля нет — живые; `gameFor(settings)` — описание игры для новой раздачи (на телефонах — `GAMES[settings.game]`, нет поля — холдем) или `null`. Игра (#80, Р-33) — `settings.game`: `'holdem'`, `'omaha'` или `'shortdeck'` (#81, Р-34) (нет поля — холдем, и у столов до #80), при любых картах; `settings.limit` — `'pot'` или `'nolimit'`, только у омахи (нет поля — пот-лимит); `limitFor(settings)` — предел новой раздачи: омаха — по настройке, холдем и шорт-дек — всегда `'nolimit'`; значение не из списка — отказ в `settingsError`
- **Время** (#75, Р-24) — настройки стола `turnSeconds` (время на ход: `null` — выкл, иначе целое `TURN_MIN_S`…`TURN_MAX_S` = 10…300 с) и `autoStart` (раздача «сама»: `'off'`, `'fast'`, `'medium'`, `'slow'` — пауза `AUTO_START_MS` 3 / 6 / 10 с); у столов до #75 полей нет — выкл. Меняет их ведущий между раздачами (`tableSettings`; в раздаче — «Настройки стола меняются между раздачами»), действуют со следующей. После каждого `handle` срок пересчитывается: новый ход — `now + turnSeconds`, тот же — прежний; перерыв, выкл или торги закрыты — `null`. `nextHandAt` ставится, когда раздача кончилась (`finishHand`: при живых картах — после `award`), на «Продолжить» между раздачами и при включении в настройках (если раздачи уже были); снимается на старт и «Перерыв». Ставится, только когда играть есть кому — двое и больше с фишками и не `sittingOut` (#106). После каждого `handle` между раздачами (`rearm`) срок сверяется с этим: стало двое (докуп между раздачами, возврат в раздачи, `sit`, `setStack` с нуля, ребай турнира) — ставится `now + AUTO_START_MS`, уже стоящий не сдвигается; стало некому — снимается; идущая раздача не трогается. `nextDeadline(state)` — ближайший срок стола для будильника сервера. `onTime(state, now, deck)` — чистая функция будильника: истёк тот же ход (`hand`, `move`, без перерыва) — то же, что `skip` (чек, если можно, иначе пас), запись хода с `timeout: true`, +1 в `timeouts`, `TIMEOUTS_TO_SIT_OUT` = 2 подряд — `sittingOut`; свой ход игрока или «Вернуться в раздачи» — счёт с нуля; пора `nextHandAt` — `start` с колодой сервера (не вышло — меньше двоих с фишками или перерыв — срок снят, ждёт ведущего); рано, повторно или ход уже сделан — `null`, стол не меняется. «Перерыв» (`pause`, только ведущий) — `start` отказывает «Перерыв — сначала «Продолжить»», идущая раздача доигрывается без таймера; «Продолжить» — ход получает полное время заново

- **Турнир** (#78, Р-28, `tournament.ts`) — режим стола `settings.format`: `'cash'` (по умолчанию; у столов до #78 поля нет) или `'tournament'` со структурой `settings.tournament` (`TournamentSettings`: `buyIn` — целые рубли, `scheme` — `'classic'` / `'percent'`, `growthPct` 1…200, `levelMinutes` 1…120, `antePct` 0…100, `rebuyLevels` — ребай до конца уровня N, 0 — без, `prizes` — проценты по местам, сумма 100, до 10 мест, `null` — по числу игроков); `sb`, `bb`, `startingStack` стола — стартовые. Уровень — чистой функцией `clockAt(t, clock, now)`: от старта минус паузы, идущая пауза — до её начала; номер и мс до следующего. После раздачи без фишек — выбыл (`out`: игрок, номер раздачи, стек до неё; выбыли в одной — по возрастанию стека, `addBusts`); остался один не выбывший — `endedAt`, новая раздача — отказ «Турнир окончен», раздача «сама» не ставится. Ожидание ребая (#94): остался один, а ребай открыт (`waitingRebuy`), — `endedAt` не ставится, раздача «сама» тоже, раздача не начинается (с фишками один); выбывший делает ребай — снова в игре, раздача «сама» взводится; ребай закрылся по часам (`rebuyClosesAt` — старт + паузы + `rebuyLevels` уровней; на перерыве часы стоят — срока нет; ребай до конца последнего уровня не закрывается) — `endedAt` = минута закрытия: в любом `handle` и в `onTime` (`closeRebuyWait`), `nextDeadline` ждёт и этот срок; ведущий шлёт `endTournament` («Закончить турнир», только пока с фишками один; иначе — «Закончить турнир — когда с фишками остался один») — `endedAt` = сейчас. Места и призы — те же `standings`. Места (`standings`): не выбывшие по стеку, затем выбывшие — позже выбыл выше. «Ребай» (`tournamentRebuy`) — сам выбывший, без ведущего, пока уровень по часам ≤ `rebuyLevels` (`rebuyOpen`): стек — стартовый, запись `rebuy` в журнале фишек (`by` — он сам), `buyIn` растёт; после — «Ребай был до конца уровня N». В турнире докупы кэша (`rebuy`), правка стека и посадка после старта — отказ; «Убрать со стола» — выбывает сразу (`out` с номером прошедших раздач), фишки уходят; после конца турнира убрать нельзя. Призы до старта — `tableSettings.prizes` (после — «Призы меняются до начала турнира»)
- **HUD вечера** (#79, Р-32, `hud.ts`) — поле стола `hud` (`Hud`: по id игрока `HudCounts` — `hands`, `vpip`, `pfr`, `stealChances`/`steals`, `cbChances`/`cbs`, `raises`, `calls`); у столов до #79 поля нет — с нуля. - **Запросы:** `GET /` — «Сервер покера «Фишек» работает, протокол N». `POST /rooms` — `CreateRoomRequest` → код комнаты, id и токен ведущего; из настроек стола — только `sb`, `bb`, `startingStack`, `maxSeats`, `rebuyMaxBB`, `cards`, `turnSeconds`, `autoStart`, `felt`, `cardBack`, `format`, `ante`, `tournament` (структуру турнира проверяет стол), `publicHud`, `game`, `limit`; из списка постоянных берутся только `{ id, name }` со строками, без повторов id, не больше `MAX_ROSTER` = 30; `regularId` не из списка — ведущий гость; проверки по порядку: версия («обновите приложение»), секрет `ROOM_PASSWORD` («На сервере не задан пароль»), пароль («Неверный пароль»), место в реестре («Комнат уже 10»), стол (`createTable`). Сайт на другом адресе — ответы с разрешением CORS. `GET /rooms/<код>` — WebSocket в комнату; кода нет — «Комнаты нет» и соединение закрыто
- **Комната** (объект `Room`, одна на код) — запись `room` в хранилище объекта: `{ code, table, tokens, roster, lastMoveAt }`; `roster` — постоянные, отмеченные ведущим (у комнат протокола 1 нет — пустой список). WebSocket со сном (`acceptWebSocket`): в памяти ничего не держится — стол читается из хранилища на каждом сообщении и пишется после; кто на соединении — отметка на сокете (`serializeAttachment`). Сразу после подключения комната шлёт `lobby`: список и id постоянных, уже сидящих за столом. Первое сообщение клиента — `join`: с верным токеном — возврат на своё место (старое соединение того же игрока закрывается), без токена или с чужим — посадка новым: с `regularId` — под постоянным, имя из списка («Такого игрока нет в списке комнаты» — если нет), без него — гостем под именем; отказ посадки — причина и свежий `lobby`. `reseat` (только ведущий, не себя) — новый токен игроку: ведущему `reseated` для ссылки, старый токен больше не пускает, соединения игрока закрываются (`CLOSE_REPLACED`), он вне сети. Остальное — в `handle` стола; на `start` при картах на телефонах комната тасует колоду (`newDeck`: `shuffle(deckFor(gameFor(settings)))`, случайность — `env.random`, нет — Web Crypto) и подаёт её столу — тем же путём и раздаче «сама» из будильника. Удачный ход — всем вошедшим `state` (с `now` — временем сервера): каждому свой вид стола (`viewFor` по игроку соединения — без колоды и чужих закрытых карт; при живых картах — весь стол), отказ — `error` только приславшему; `ended` — тоже в виде телефона. Возврат по токену и «пересадить» приносят свои карты — они в столе на сервере. Чужая версия в любом сообщении — «обновите приложение», соединение закрыто. Закрылось последнее соединение игрока — он вне сети (`setOnline`). На `PING` отвечает сама платформа, объект не просыпается (`setWebSocketAutoResponse`); последний признак жизни соединения — позднее из времени ответа (`getWebSocketAutoResponseTimestamp`) и входа (`joinedAt` в отметке). Ведущий ведёт стол как раньше; ведущий вне сети, пока не вошёл
- **История раздач** (#113): каждая раздача — своей записью хранилища объекта `hand:000012` (`handKey`, номер с нулями — по порядку ключей; `HistoryHand` полностью, с `hidden`), не в записи `room`: та пишется целиком и уходит всем на каждый ход, а значение хранилища — не больше 128 КиБ. Пишется (`keepHand`) после удачного хода и срабатывания будильника, до записи стола, когда `finishedHand` что-то дал: раздача окончилась (ходом, по таймеру) или «Показать» переписал её запись. Вошедший шлёт `history` — ему одному ответ `history`: все записи по порядку номеров (`list` с префиксом `hand:`), каждая в его виде (`handFor`); не вошедшему — «Сначала войдите в комнату». Состояние стола в `state` от числа раздач не растёт
- **Пропавшие молча** (#64): будильник один на комнату; пока за столом кто-то в сети, он срабатывает раз в `CHECK_MS` = 20 с (вход ставит его, если назначенный дальше). Соединение игрока молчит дольше `SILENT_MS` — закрывается (`CLOSE_SILENT`, клиент переподключается), игрок без других соединений — вне сети с последнего признака жизни; в сети по столу, а соединения нет (перезапуск сервера) — вне сети с момента проверки. Худший случай до «вне сети» — `PING_MS` + `SILENT_MS` + `CHECK_MS` ≈ 50 с после пропажи; «Взять ведение» — через `HOST_TAKEOVER_MS` после последнего признака, меньше двух минут. Никого в сети — будильник на сутки после последнего хода. Ведение само не переходит
- **Сроки стола** (#75): тот же будильник — ближайшее из суток после последнего хода, `now + CHECK_MS` (кто-то в сети) и `nextDeadline` стола (`nextAlarm`); после каждого удачного сообщения и входа он переводится раньше, если нужен раньше (`wake`), и не отодвигается. Срабатывание — сначала живость, затем `onTime` стола с колодой `newDeck`: истёкший ход, раздача «сама» или закрытие ребая, пока его ждут (#94: турнир окончен и без ведущего в сети), — всем `state`; рано или повторно — стол не меняется и не рассылается. Ход по таймеру и раздача «сама» `lastMoveAt` не двигают: брошенная комната доигрывает, пока все не «пропускают раздачи» (два истечения подряд), и стирается через `IDLE_MS` после последнего хода людей. Ведущий вне сети или телефоны спят — сроки идут сами
- **Конец комнаты:** ведущий шлёт `finish` или будильник видит сутки без ходов (`IDLE_MS`; ставится при создании, а без игроков в сети — на сутки после последнего хода) — всем `ended` со столом на этот момент, соединения закрыты, хранилище стёрто (с историей раздач), место в реестре освобождено. Повтор будильника после стирания ничего не делает
- **Реестр** (объект `Registry`, один) — коды живых комнат, не больше `MAX_ROOMS` = 10. Код — 6 знаков без похожих (`CODE_ALPHABET`). Реестр полон — комнаты старше минуты спрашиваются, живы ли (`alive`), мёртвые вычеркиваются
- **Пределы бесплатного плана** кончились — ошибка подключения к серверу; сайт и учёт вечера от сервера не зависят

## Сборка и выкладка

Vite, `base: '/Magic_Fishki/'`; PWA — `vite-plugin-pwa` (манифест, работник, иконки, `apple-touch-icon` для iPhone). Манифест — `fishki.webmanifest`, `id` — `/Magic_Fishki/fishki`, запуск — `/Magic_Fishki/?app=fishki` (Р-06, Р-08): не меняются никогда. На Android Play Защита может предупредить «для более ранней версии Android» — «Всё равно установить» (оболочку собирает Chrome, не мы). GitHub Pages — `.github/workflows/deploy.yml` на пуш в `main`.

Сервер комнат — `.github/workflows/server.yml` на пуш в `main` с правкой `server/`, `src/poker/` или зависимостей: тесты, типы сервера, `npm run server:deploy` (`wrangler deploy`); нет секретов `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` — выкатка пропускается. В «Проверках PR» — `npm run server:check` (типы) и `npm run server:build` (`wrangler deploy --dry-run`).
