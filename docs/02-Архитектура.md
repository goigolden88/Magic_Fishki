# Архитектура

## Модель данных

```ts
type Game = {
  id: string            // ULID
  name: string          // «Пятница у Кирилла»; по умолчанию — дата
  date: string          // YYYY-MM-DD, день игры
  rate: number          // рублей за фишку: 0.5 — фишка по 50 копеек
  players: Player[]
  entries: Entry[]
  casino?: CasinoRound[] // раунды казино (Р-13); нет — казино не было
  closed?: boolean      // игра закрыта: записи не правятся без «Открыть снова»
  demo?: boolean        // демо-данные — удаляются одной кнопкой
  updatedAt: string     // ISO 8601
}

type Player = {
  id: string
  name: string          // копия имени на момент игры: правка постоянных её не трогает
  regularId?: string    // id постоянного игрока (Р-12); нет — гость
}

type Regular = { id: string; name: string } // постоянный игрок: id не меняется при переименовании (Р-12)

type Entry = {
  id: string
  playerId: string
  kind: 'buyin' | 'rebuy' | 'cashout'
  chips: number         // целое, > 0
  at: string            // ISO 8601, ставится само
}

type CasinoRound = {    // раунд казино (Р-13): сумма долей — ноль
  id: string
  amounts: { playerId: string; kopecks: number }[] // доля участника в копейках, целое, не 0
  at: string            // ISO 8601, ставится само
}

type Settings = {
  defaultRate: number     // курс новой игры; по умолчанию 0.5
  players?: Regular[]     // постоянные игроки — отмечены в новой игре (Р-07, Р-12); нет — пусто
  quickAmounts?: number[] // быстрые суммы у «Закуп», «Докуп», «Выход» (Р-07); нет — [500, 1000, 2000]
}
```

**Связь с постоянным игроком** (Р-12): `regularId` ставится при создании игры из отмеченных постоянных (по их id), при добавлении участника на экране игры и в игре из Телеграма — по точному совпадению имени (`linkRegulars`, `src/model.ts`). Переименование постоянного меняет только `name` в настройках — id и связи прошлых игр остаются.

## Расчёт — `src/calc/`

- **Итог игрока:** `out − in`, где `in` — сумма закупов и докупов, `out` — сумма выходов (обычно один). В рублях — `× rate`, хранится и считается в копейках, округление — до копейки
- **Сходится ли игра:** сумма `in` всех = сумма `out` всех. Не сходится — итог показывает разницу словами и переводы не считает: «не хватает 500 фишек: у кого-то не записан выход»
- **Казино** (Р-13, `src/calc/casino.ts`): раунд вводится строками `Эрик, Артём +150` — каждый названный получает число в рублях, без знака — плюс; имя дважды — сложено (`parseRound`). Раунд добавляется, только если в ноль и все строки разобраны; имя не из игры — новый участник только казино (без покерных записей, связь с постоянным по имени). Три итога участника (`gameResult`): покер — копейки из фишек (`playerTotals`), казино — сумма долей, итого — их сумма. Игра сходится — покер сходится и все раунды в ноль; игра без закупов — только казино
- **Статистика постоянных игроков** (`src/calc/stats.ts`): только закрытые игры без `demo`, только участники с `regularId` из настроек (гости — нет); строка — по id постоянного, имя — из настроек. Итоги — покер, казино и итого (Р-13); итог в рублях — сумма копеек «итого» по играм (у каждой свой курс); игр и в плюсе; лучший и худший вечер — по рублям «итого»; докупы — число записей `rebuy`, среднее за игру. Порядок — по рублям, сверху самый большой плюс, без игр — внизу
- **Динамика игрока** (`src/calc/trend.ts`, `playerTrend`): те же закрытые игры без `demo`, в которых есть участник с этим `regularId` (дважды в игре — один вечер), новые первыми — как на «Играх» (дата, затем `id`). Окна — последние 5 и предыдущие до 5, по «итого»: итог в копейках, в плюсе, средний итог за игру (целые копейки), докупов в среднем. Разница последних с предыдущими по каждому показателю; предыдущих меньше 5 — итог и «в плюсе» предыдущих приводятся к числу последних (по средним); лучше — больше, для докупов — меньше
- **Переводы:** жадно — самый большой должник платит самому большому получателю, пока все не на нуле. Переводов не больше «игроков с ненулевым итогом − 1». Проверка в тестах — пример со скриншота: 6 игроков, 5 переводов. Без казино — в фишках, рубли из фишек; с казино — по «итого» в копейках (Р-13): при дробном курсе сумма копеек покера может отличаться от нуля на копейку — она остаётся без перевода
- Всё — чистые функции с тестами

## Хранение

IndexedDB, база `magic_fishki`, версия 2: хранилища `games` (ключ `id`) и `settings` (одна запись). Новая версия — шагом миграции, старые записи не теряются.

- **1** — хранилища `games` и `settings`
- **2** (Р-12) — `settings.players` из строк в `{ id, name }` с новыми id в прежнем порядке; участникам сохранённых игр с точно тем же именем — `regularId`; остальные поля игр, в том числе `updatedAt`, не меняются. Другая вкладка на версии 1 закрывает базу по `onversionchange`

**Файл-копия** (Р-11) — `fishki-ГГГГ-ММ-ДД.json`: `{ app: 'magic_fishki', format: 2, savedAt, games, settings }`, игры — все, кроме `demo: true`; в формате 2 (Р-12) постоянные игроки — `{ id, name }`, у участников — `regularId`; раунды казино (Р-13) — в игре, формат тот же: раунд не в ноль — битая игра, копия без поля — игра без казино. Через «Поделиться» — тот же текст в `.txt` (Chrome на Android не делится `.json`); восстановление принимает оба. Восстановление: файл проверяется целиком (не копия, новее `format`, битая игра — ошибка, данные не меняются); копия формата 1 при разборе приводится к формату 2 — постоянным новые id, участникам связь по точному имени; игры, которых нет по `id`, пишутся как есть (`restoreGames`, со своим `updatedAt`, одной транзакцией), с тем же `id` — не трогаются; из настроек берутся только постоянные игроки: с тем же id — уже есть, остаётся свой; с тем же именем — один человек, связи в добавленных играх переводятся на здешний id; прочие дописываются со своим id. Разбор и слияние — `src/calc/backup.ts`.

## Экраны

- **Игры** — список, новые сверху; «Новая игра»; в шапке — «Игроки» и «Настройки»
- **Игроки** (`#/players`) — статистика постоянных по всем закрытым играм: «По N закрытым играм из M»; у каждого итого в рублях, строкой — покер (рубли и фишки), казино, итого, «игр N, в плюсе M», лучший и худший вечер (сумма, дата, название), докупов всего и в среднем за игру; закрытых игр нет — «Закрытых игр пока нет». Касание игрока — его карточка. Только читает
- **Карточка игрока** (`#/players/:id`) — за всё время, как в списке; ниже «Последние 5 игр» и «Предыдущие 5 игр» рядом: итог, в плюсе из N, средний итог, докупов в среднем; у последних — разница со стрелкой (▲ лучше, ▼ хуже). Игр 5 и меньше — только последние и «для сравнения нужно больше 5 игр»; от 6 до 9 — предыдущих сколько есть, пояснение «сравнение по средним»; без закрытых игр — «игр нет». Только читает
- **Игра** — участники; у каждого — записи и кнопки «Закуп», «Докуп», «Выход» (участник только казино — «только казино» вместо «закуп · выхода нет»); блок «Казино» — раунды и «Добавить раунд»: поле строк, предпросмотр «игрок → ₽», «Раунд не сходится на N ₽», новые имена — после подтверждения; раунд удаляется вторым нажатием, в закрытой игре не правится; итог и переводы внизу — с казино таблица «покер / казино / итого» в рублях
- **Итог для мессенджера** (`src/calc/share.ts`) — с казино строки «Покер:», «Казино:», «Итого:»; только казино — «Казино:», заголовок без курса
- **Настройки** — курс по умолчанию, постоянные игроки, быстрые суммы (Р-07); «Копия игр»: «Сохранить копию», «Поделиться копией» (где браузер умеет делиться файлами), «Восстановить из копии» — «Добавлено N, уже были M» (Р-11); «Демо-данные»: добавить / удалить — ещё не сделано (План, п. 1)
- **Из Телеграма** (`#/import`, Р-10) — вставка скопированных сообщений `#rebuy` / `#cashout` → сверка (дата, курс, игроки: закуп, докупы, выход; добавить, переименовать, объединить, убрать; «не разобрано: N строк»; сходимость — той же функцией) → «Создать игру» — обычная игра со временем сообщений. Разбор — `src/calc/telegram.ts`

## Сборка и выкладка

Vite, `base: '/Magic_Fishki/'`; PWA — `vite-plugin-pwa` (манифест, работник, иконки, `apple-touch-icon` для iPhone). Манифест — `fishki.webmanifest`, `id` — `/Magic_Fishki/fishki`, запуск — `/Magic_Fishki/?app=fishki` (Р-06, Р-08): не меняются никогда. На Android Play Защита может предупредить «для более ранней версии Android» — «Всё равно установить» (оболочку собирает Chrome, не мы). GitHub Pages — `.github/workflows/deploy.yml` на пуш в `main`.
