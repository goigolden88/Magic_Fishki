### Р-06 · Постоянный `id` манифеста — `/Magic_Fishki/fishki`
09.10.2026

- **Как было:** `id` не задан — Chrome берёт его из `start_url`; первая установка на Android не завершилась, и Chrome считает приложение установленным.
- **Решено:** `id: '/Magic_Fishki/fishki'`, явные `start_url`, `scope`, полные пути иконок, отдельная маскируемая иконка — по образцу манифеста семьи.
- **Почему:** новый `id` — новое приложение для Chrome, без застрявшей записи; явные поля — то, что уже работает на этом телефоне.
- **Цена:** `id` после этого не меняется никогда: смена превращает установленное приложение в другое. Сейчас установленных копий нет.
- **Миграция:** нет.

### Р-10 · Игра из Телеграма — вставка текста `#rebuy` / `#cashout`, сверка, обычная игра
11.10.2026

- **Как было:** игра вводится только руками; вставка из Телеграма — в Плане без правил.
- **Решено:** «Из Телеграма» на «Играх»: вставка текста формата `[ДД.ММ.ГГГГ Ч:ММ] Отправитель: текст` → экран сверки → обычная игра. `#rebuy [имя]` — докуп на `defaultBuyin`; `#cashout [имя] N` — выход N; без имени — отправитель. Каждому игроку из текста — один закуп на `defaultBuyin`. На сверке — добавить, переименовать, объединить, удалить игрока, поправить числа; проверка сходимости — та же функция, что у игры. Время записи — время сообщения. Распознавания фото нет.
- **Почему:** просьба владельца 11.10.2026; копирование текста в Телеграме даёт точные имена и числа без библиотеки распознавания (фото — новая зависимость и ошибки в цифрах). Кто вышел с нулём, в чате не пишет — поэтому сверка, а не запись сразу.
- **Цена:** формат копирования — Телеграма: изменит его Телеграм — разбор перестанет узнавать строки (на сверке это будет видно: «не разобрано»). Ники и имена сопоставляются руками каждый раз.
- **Миграция:** нет.

Выбор владельца — блок «Решение» в #17; перенесено исполнителем.

### Р-12 · Постоянный игрок — `{ id, name }`; участник игры связан с ним через `regularId`
14.10.2026

- **Как было:** постоянные игроки — строки в настройках (Р-07); участник игры — свой id в каждой игре; связи между играми нет, переименованный игрок — новый человек.
- **Решено:** постоянный игрок — `{ id, name }` в настройках; у участника игры — необязательное поле `regularId` (id постоянного). Связь ставится при создании игры из постоянных, при добавлении участника с именем постоянного и в игре из Телеграма — по точному совпадению имени. Имя участника в игре — по-прежнему копия.
- **Почему:** статистика игроков (План, п. 2) и будущие модули («Покер») — по человеку, а не по строке; переименование не должно делить историю. Игр пока мало — миграция дешёвая; «сначала по имени, потом id» — двойная работа.
- **Цена:** игрок, убранный из постоянных и добавленный снова, получает новый id — его история не склеится; совпадение имени точное (регистр и пробелы важны). Копии прежнего формата восстанавливаются по имени.
- **Миграция:** версия базы 1 → 2. Шаг: запись настроек — `players` из строк в `{ id, name }` с новыми id в прежнем порядке; в каждой сохранённой игре участникам, чьё имя точно совпало с постоянным, проставить `regularId`. Остальные поля игр не меняются. Перезапись записи настроек — сверх «только добавляет»: владелец разрешил её явно 14.10; копия (#23) — до слияния этой задачи.

Выбор владельца — блок «Решение» в #25; перенесено исполнителем.

### Р-14 · Покер через интернет — в «Фишках»; сервер — Cloudflare Workers + Durable Objects
16.10.2026

- **Как было:** «Фишки» — учёт вечера на одном устройстве, без сервера; цифровые фишки и игра с нескольких телефонов отложены «отдельным решением» (01, «Потом»). Онлайн-покер владельца — отдельный прототип на ноутбуке.
- **Решено:**
  - Покер через интернет живёт в «Фишках». Результаты сыгранной онлайн-игры сразу становятся игрой в истории — с участниками-постоянными (Р-12) и переводами (Р-03). Учёт вечера — часть покерного приложения.
  - Сервер — Cloudflare Workers + Durable Objects: одна комната — один объект, таймер хода — будильник объекта. Бесплатного плана хватает компании друзей.
  - Учёт вечера с живыми фишками работает без сервера и без сети, как сейчас.
  - Этапы:
    1. Движок прототипа — на TypeScript вместе с тестами. Сервер комнат на Cloudflare. Режим «живые карты, цифровые фишки»: карты на столе настоящие, ставки и банк — с телефонов; итог — игрой в историю.
    2. Полная игра через интернет с картами: каждый видит свои карты на своём телефоне.
    3. Потом: помощник с графиками (`Shtab#10`). Разбор истории раздач — навыком агента, не кодом приложения.
- **Почему:** владельцу удобно держать покер и учёт в одном месте, чтобы результаты сразу шли в историю. Сервер закрывает отложенное «цифровые фишки с нескольких телефонов». Без сервера закрытые карты не спрятать: каждый должен видеть свои на своём телефоне. Cloudflare: у владельца уже есть аккаунт (приёмник Штаба), есть бесплатный план и WebSocket со сном между сообщениями. Свой ноутбук как сервер не годится: он должен быть включён и доступен из интернета.
- **Цена:**
  - Первый свой сервер. Нужны ключ, деплой руками владельца, строка в аварийном плане и описи токенов («Свой проект с сервером», Ш-117).
  - Клиент прототипа переписывается на React/TS приложения; движок переносится с тестами.
  - Онлайн-игроков нужно связать с постоянными.
- **Миграция:** нет (только документы).

Выбор владельца — блок «Решение» в #44; перенесено исполнителем.
