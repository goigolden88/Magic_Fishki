# CLAUDE.md

**«Фишки»** (`goigolden88/Magic_Fishki`) — учёт покерных вечеров с друзьями: кто сколько закупил, докупил и вывел → итог каждого в фишках и рублях → минимум переводов «кто кому». Заменяет сообщения `#rebuy` / `#cashout` в Телеграме и ручной расчёт таблицей (`docs/01-Проект.md`).

**Стек:** Vite + React + TypeScript (`strict`), хеш-роутинг, обычный CSS. Хранилище на устройстве — IndexedDB. PWA: ставится на iPhone и Android с экрана браузера, работает без сети. Бэкенда и синхронизации нет. Сайт — GitHub Pages, `base` сборки — `/Magic_Fishki/`.

Проект вне семьи приложений: ядра `FamilyCore` здесь нет и не будет без отдельного решения (пилот 2Ж «Штаба»).

## Документы

Лежат в `docs/` и являются источником истины. Код им подчиняется, а не наоборот.

- `01-Проект.md` — зачем, границы, что будет потом
- `02-Архитектура.md` — модель данных, расчёт, хранение, структура кода
- `03-План.md` — что предстоит
- `05-Решения.md` — решения «Р-NN» и почему так

## Как работать

1. Сверяйся с `02-Архитектура.md` перед тем, как писать код. Имена полей и типы берутся оттуда.
2. Отступление от Архитектуры или решения — вслух и до кода. Молча менять модель нельзя.
3. Решение записывается в `05-Решения.md` сразу. Старые записи не переписываются: отмена — новая запись со ссылкой.

## Правила кода

- Расчёт — чистыми функциями в `src/calc/` с тестами (Vitest); экраны тестами не покрываются
- К IndexedDB — только через `src/store/db.ts`
- Схема хранилища версионируется с первого дня (`version` базы), миграции пишутся сразу
- Деньги — в копейках целыми, фишки — целыми; дробный только курс (рублей за фишку)
- Зависимости — только нужные: React, Vite, `vite-plugin-pwa`, Vitest, `fake-indexeddb` для тестов; для сборки — TypeScript и типы React (`@types/react`, `@types/react-dom`), Р-05. Новая — через решение
- Интерфейс и комментарии на русском, имена в коде на английском

## Правила интерфейса

- **Запись — в одно касание:** игрок → «Закуп», «Докуп» или «Выход» → число. Время ставится само
- **Число — с основанием:** итог показывает, сходится ли игра: «выведено 11 000 из 11 000 фишек» или «не хватает 500 фишек — у кого-то не записан выход»
- Крупные кнопки: играют вечером, с телефона, одной рукой

## Для конвейера

Агенты конвейера «Штаб» (`goigolden88/Shtab`) работают здесь без человека: берут issue с меткой `готово`, присылают PR, сливает только человек. Правила выше действуют целиком; здесь — только то, что агенту нужно сверх них.

- **Клон:** `npm ci` (после первого PR, где появится `package.json`; в пустом репо — `npm install`, и `package-lock.json` — в коммит)
- **Проверки перед PR:** `npm test`, `npm run build` (в нём `tsc --noEmit`) — итог по коду выхода. Те же гоняет CI на каждый PR («Проверки PR»)
- **Только через `нужно-решение`:** всё, что меняет хранимые данные пользователей (схема IndexedDB после первого релиза); новая зависимость сверх перечисленных; правка `.github/`, этого файла и `docs/`
- **Блок «Решение»** в тексте issue (Штаб, Ш-37, Ш-44) — решение владельца, принятое до задачи: перенести его в `docs/05-Решения.md` следующим номером Р-NN, в том же PR, что и код
- **Данные:** реальных игр в репо нет — он публичный; демо-данные — выдуманные имена и числа
- **Отчёт** — в описании PR, по шаблону Штаба; `docs/03-План.md` агент не правит
- **После слияния** сайт выкатывается сам из `main` (`deploy.yml`) на `https://goigolden88.github.io/Magic_Fishki/`; проверка — на телефоне: открыть, «На экран Домой», шаги — в отчёте
